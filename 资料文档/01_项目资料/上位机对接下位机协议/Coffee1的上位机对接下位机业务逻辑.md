# Coffee1（close_v2.7.23_ccram）上位机↔下位机通讯协议业务逻辑梳理

## 一、总体架构与通讯承载

| 链路                     | 方向 / 角色                           | 承载协议                     | 端口 / 说明                       |
| ------------------------ | ------------------------------------- | ---------------------------- | --------------------------------- |
| 嵌入式板 **服务端**      | 上位机(安卓屏/云平台)主动连接嵌入式板 | **Modbus-TCP**（服务端监听） | **6001**，最多 4 客户端           |
| 嵌入式板 **客户端**      | 嵌入式板主动连接机器人                | **Modbus-TCP**（客户端）     | 机器人端口 502                    |
| 嵌入式板 主站 ↔ 外围设备 | 主–从                                 | **Modbus-RTU（RS485）**      | 咖啡机/落杯/落盖/制冰/糖浆/IO模块 |

- 上位机对下位机的**全部业务控制**走 Modbus-TCP 功能码：
  - `0x03` 读保持寄存器（上位机读状态）
  - `0x06` 写单个寄存器（**命令 / 单步调试入口**）
  - `0x10` 写多个寄存器（**订单数据批量下发**）
  - 异常响应：功能码|0x80 + 异常码（如 0x06 从站忙碌）
- 数据模型三块：**输入寄存器(Input)**＝上位机→下位机命令/订单；**保持寄存器(Holding)**＝下位机→上位机状态/完成报告；**线圈(Coils)**＝嵌入式板↔机器人握手位。
- 上位机单元标识符恒为 `0x01`，非 0x01 帧直接丢弃。

## 二、寄存器方向总表（重点，含修正）

> 重要区分：**0x32/0x33 是下位机写给机械手的目标命令，不是状态反馈**；储位“有无杯”反馈在 **0x1027**，出餐口取餐状态在 **0x100B/0x100C**，出餐口机构状态在 **0x1090~0x1092**。

## 三、版本号来源（Flash 分区实况）

- **版本号是 App 编译期字符串宏，不是从 Flash 分区运行时读取**：
  ```c
  // Core/Src/main.c:62-73
  #define DEVICE_VERSION  "close_v2.7.23_202608061810"   // 改这里→重新编译烧录
  const char g_device_version[] = DEVICE_VERSION;
  ```
  `tcp_server` 写 `0x0202=1` 打印的就是它。
- **Flash 分区实际用途**：
  - `0x08000000` 扇区0 → **Bootloader**（`coffee_bootloader/bootloader_v2.0.bin`）
  - **`0x08004000~0x08007FFF` 扇区1 = CONFIG_BASE** → **OTA 配置标志区**（写入 `ota_config`：固件大小/CRC/标志，见 `ota/httpserver.c:1137-1140`）。**不是版本号分区**。
  - `0x08008000` 扇区2 = `MACHINE_TYPE_FLASH_ADDR` → **机型配置**（`machine_type_t`，含 `store_cup_valid`、`machine_select`、果乳系数等，'W''N' 头 + size 校验）。
  - `0x0800C000` 扇区3 = **APPLICATION_BASE = 当前 App 所在地址**（OTA 跳转目标）。
  - `0x08040000` = OTA 临时缓冲/新固件区。

## 四、存储位使用逻辑（完整梳理）

### 4.1 开店配置
上位机写 `0x001A store_cup_valid`（储位开设位图，掉电保存）→ 下位机存入 `machine_type`（0x08008000）。每个储位的硬件好坏由 IO 板 **X1~X12** 传感器实时采集。

### 4.2 储位状态上报（下位机→上位机，HOLD）
```
0x1027 store_cup_stat = Σ ( Xn 传感器有杯 ∧ store_cup_valid 第n位已开启 )，bit(n-1)=1 表示第n储位有杯
```
即：“**有没有杯 / 哪些位有杯**”的反馈在 **0x1027**，不是 0x32/0x33。

### 4.3 线上单下单 → 生产 → 暂存储位
1. 上位机写订单 `0x0000~0x0006` → `0x0007 has_order=1` → 下位机镜像参数到 HOLD → 写 `0x0008 order_check_result=1` → `production_status=1`，开始生产。
2. 生产完成（线上单，v2 订单号高4位≠0xD，判定**不进储藏台**）→ `E_FLOW_REPORT_PLACE_POS`：
   - **暂存到哪个储位，是下位机用 `io_input_store_cup_idle()` 自动挑选空储位，不是上位机指定**。
   - 下位机把该位在 `0x1027` 对应位置1（有杯）、把位号写进 `0x100A cup_storage`，并写 `0x0032 store_cup_pos_to_robot = 位号` 让机器人去放。
3. **可以继续接新单**：一单入储位后 `E_FLOW_IDLE` 复位，下位机空闲即可做下一单 → 多杯累积在不同空储位（0x1027 多位为1）。

### 4.4 付款后取出（核心交互）
1. 上位机确定取哪杯 → 写 **`0x0009 take_store_cup = 储位号(1~12)`**、写目标窗口 **`0x000A(v3) 或 0x000C(v2现场)`**，并把 **`0x0007 has_order / 0x0008 order_check_result` 清0**（表示这是一次独立取餐任务，不是在做单）。
2. 下位机 `E_FLOW_IDLE` 判到取餐条件：
   ```
   has_order==0 && (food_pickup_window==1||2) && (1<=take_store_cup<=12) → 取餐流程
   ```
3. 下位机校验：`0x1027` 该储位对应位=1（确有杯）且目标出餐口非报警（`0x1090` 非0x03/0x30）→
   - 写 `0x0032 = take_store_cup`（给机械手的取杯位）
   - 写 `0x0033 = 出餐口`（给机械手的放餐口）
   - 机器人去储位取杯 → 放到出餐口 → 出餐机构放杯 → 清储位位（0x1027 该位清零）、更新 `take_food_stat1/2`、`production_status` 上报成功。
   - 若储位无杯 / 窗口故障 → `take_food_stat1/2 = 0x03`（失败），恢复储位状态。
4. **结论：取哪杯、放哪口由上位机给（0x09/0x0A/0x0C）；物理点位号经 0x32/0x33 下发给机械手；储位“有/无杯”状态反馈走 0x1027；出餐口取餐结果走 0x100B/0x100C。**

### 4.5 普通出餐（线下 v2 现场单 / v3 全单）
- **不暂存储位**，机器人直接把成品放到出餐口：下位机只写 `0x0033 food_pickup_window_to_robot = 出餐口`（v2 现场单取值源自 `0x000C`，v3 源自 `0x000A`），`0x1027` 储位不改变。

## 五、按任务分类的业务逻辑

### 5.1 订单制作流水线
```
IDLE → START → TO_CUP_POS(落杯机) → GET_CUP(落杯) → TO_COFFEE_RDY → TO_COFFEE →
COFFEE_START(咖啡机,糖浆/果乳并行出液) → COFFEE_WAIT → COFFEE_FINISH →
  需要盖子：TO_LID(落盖) → COVER_LID(压盖)   [v1 还需 TO_PRINT 打印]
→ 路由出口：
   需要直接出餐 → GOTO_FOOD_PICKUP_WAIT → 出餐口
   否则(线上单/封闭式) → REPORT_PLACE_POS → 放存储位
→ TO_HOME → IDLE
```
- 出餐口路由由 `FLOW_SHOULD_GOTO_PICKUP` / `FLOW_GET_PICKUP_WINDOW` 决定：
  - v2.1/v2.0：仅现场单(高4位=0xD)直出，出餐口号读 `0x000C`；线上单进储位。
  - v3：只要 `0x000A food_pickup_window!=0` 全部直出。
  - v1：无出餐口，一律放储位/托盘。

### 5.2 单步调试任务（写寄存器即触发）
见 2.1 命令/维护区表格；涉及点动咖啡机、落杯/盖、糖浆、制冰、出餐机构(Y1~Y12)、水电阀(Y13~Y16)、机器人到点(0x30/0x31)、IO 线圈读写(0x101/0x102)、OTA(0x0200/0x0201/0x0202)。

### 5.3 热水/加热任务
- 命令：`0x0080 加热开始`、`0x0081 加热时间(分钟)`；状态：`0x1082 加水状态`、`0x1080/0x1081 低/高水位`。
- 逻辑：写 `0x0080=1` → 低水位(X18)缺水则抽水(Y13+水路阀)，水满(X19)停抽 → 加热(Y16 热水器继电器)，默认 30 分钟或按 `0x0081` 指定时长 → 到时关闭。加水 120s 未满报 `0x1082=0x0003`。

### 5.4 清洗任务
- 奶路清洗 `0x0083` → 三段状态机，重试≤3次，控 Y15，完成发咖啡机回主页。
- 糖浆机清洗 `0x0082/0x63~0x65` → `sugar_clean_enable()`，状态 0x1060=4。
- 咖啡机清洗 `0x0042` → `coffee_set_clean()`。
- 果乳通道清洗 `0x00A3~0x00A8` → 每通道独立，状态 0x10A8~0x10AD(0停/1洗/2注液)，清洗 15000ms，与订单制作互斥（清洗中要等新订单），双通道不同时出IO。

## 六、关键结论汇总

1. **版本号是 App 编译期宏（main.c 的 DEVICE_VERSION），不在 0x08004000~0x08007FFF 分区里读**；那片区域是 OTA 配置标志区。
2. **0x32/0x33 是下位机写给机械手的目标命令，不是状态反馈**；储位有/无杯反馈在 **0x1027**，取餐结果在 **0x100B/0x100C**，出餐口机构状态在 **0x1090~0x1092**。
3. **上位机让机械手放哪儿的下发是 0x09/0x0A/0x0C**：0x09=取哪个储位，0x0A(v3)/0x0C(v2现场)=哪个出餐口；下位机再转成 0x32/0x33 给机器人。
4. **暂存到哪个储位是下位机自动挑空位，不是上位机指定**；上位机只在付款后写 0x09 指定“取几号储位 → 放几号口”来触发取出。
5. 一单未结（has_order && order_check_result 且写地址≤0x0008）时上位机不能重写订单区（返回 0x06），需先写 0x0007/0x0008=0 结束。

## 七、业务细节汇总

### 5.2 单步调试任务（写单个寄存器即触发）——详细版

**机制**：上位机对某地址写一个值，`tcp_server.c::handle_write_singal_reg` 立即执行对应点动。因保护要求，多数点动**只在整机 IDLE（空闲）状态下有效**，忙碌时被拒绝并打印提示。按子系统分组如下。

#### A. 出餐口机构点动（0x0091~0x009D）——最常用联调
| 地址   | 写值  | 动作                     | 底层函数                                                     |
| ------ | ----- | ------------------------ | ------------------------------------------------------------ |
| 0x0091 | 1 / 2 | 出餐口1 升降杆 **上/下** | `food_pickup_windonw1_up/down`                               |
| 0x0092 | 1 / 2 | 出餐口1 **开门 / 关门**  | `food_pickup_windonw1_open/close_door`                       |
| 0x0093 | bit0  | 出餐口1 风扇             | 写线圈4（Y5）                                                |
| 0x0094 | bit0  | 出餐口1 灯带             | 写线圈5（Y6）                                                |
| 0x0099 | 1 / 2 | 出餐口2 升降杆 **上/下** | `food_pickup_windonw2_up/down`                               |
| 0x009A | 1 / 2 | 出餐口2 **开门 / 关门**  | `food_pickup_windonw2_open/close_door`                       |
| 0x009B | bit0  | 出餐口2 风扇             | 写线圈10（Y11）                                              |
| 0x009C | bit0  | 出餐口2 灯带             | 写线圈11（Y12）                                              |
| 0x009D | -     | **停止出餐口所有动作**   | `control_flwo_food_pickup_abort()` + `food_pickup_windonw_all_stop()` |

- 上升/开门等动作内部是**带超时与到位校验的闭环**：升降开出后需在限定秒数内读到对应限位/门位（`food_pickup_up_limit/down_limit`、`open/close_door` 传感器 X22~X25、X28~X31），超时判失败并自动回退。
- **互锁**：若`take_food_pickup1_setup`或`take_food_pickup2_setup`为1（正在自动取餐流程）或有别的手动出餐任务在跑，新的手动指令会被拒绝。
- 出餐机构线圈/传感器对照（io_output.h/io_input.h）：
  - 升降杆：Y1推/Y2缩（口1）、Y7推/Y8缩（口2）；门：Y3开/Y4关、Y9开/Y10关；风扇Y5/Y11；灯带Y6/Y12。
  - 传感器：X21/X27杯位、X22/X28升降上限、X23/X29升降下限、X24/X30开门位、X25/X31关门位、X26/X32安全光栅。

#### B. 咖啡机点动（0x0040/0x0041/0x0042/0x0047）
| 地址   | 动作                 | 底层与细节                                                   |
| ------ | -------------------- | ------------------------------------------------------------ |
| 0x0040 | 手动制作指定类型咖啡 | `coffee_set_type(reg_val)` → 经 RS485 写咖啡机寄存器 **0x2000**，带"校验应答"（区分发送失败 / 异常应答 / 正常ACK）；仅当咖啡机 `sync_id==0x00FF`（空闲）才真正写 |
| 0x0041 | 咖啡机进水泵         | `ctrl_board_out5(reg_val&1)`（水路电磁阀）                   |
| 0x0042 | 设置咖啡机清洗       | `coffee_set_clean(reg_val)` → 写咖啡机 **0x200C**（仅 sync_id==0x00FF 时，置 run_flag=0x02） |
| 0x0047 | 咖啡机取消所有任务   | `coffee_set_stop()` → 写咖啡机 **0x200E=0**（退回主页）      |

- 咖啡机全部指令走 RS485 Modbus-RTU，写指令用"写+校验应答"机制（`coffee_write_singal_register_checked`），发送失败/异常应答/ACK 三态区分；自动制作有重试（`COFFEE_MAKE_RETRY_MAX=3`）。
- 用 `sync_id!=0x00FF` 判定咖啡机"忙/异常"，`0x1042` 反映该状态。

#### C. 落杯 / 落盖（0x0050）
- 0x0050：`reg_val<2` → `cup_select_type(reg_val)`（**落杯**，0/1 对应热杯/冷杯，由订单温度 `0x0005` 决定）；`reg_val>=2` → `lid_select_no(reg_val%2)`（**落盖** 选 1/2 号盖）。
- 落杯后经 `cup_online_stat` + 落杯机寄存器状态确认落杯成功。

#### D. 糖浆机（0x0060~0x0065）
| 地址             | 动作         | 细节                                                         |
| ---------------- | ------------ | ------------------------------------------------------------ |
| 0x0060           | 糖浆使能     | `sugar_set_enable(reg_val)` → 对糖浆机寄存器`(reg_val+1)`**先写0再写1（脉冲触发）**，置 sugar_run_flag |
| 0x0061           | 出糖量       | `sugar_set_mount(reg_val)` → 写糖浆机 **0x0000**             |
| 0x0062           | 剩余时间     | `sugar_set_remaining_time(reg_val)` → 写糖浆机 **0x000A**    |
| 0x0063/0x64/0x65 | 糖浆管路清洗 | `sugar_clean_enable()` → 关奶路阀 Y15，写糖浆机 **0x05** 先0后1（脉冲触发清洗） |

#### E. 制冰机点动（0x0070/0x0071/0x007E/0x007F）
- 0x0070 `手动出冰`：`make_ice_manual_contrl()` → **仅 IDLE** 时进入 `E_FLOW_MANUAL_MAKE_ICE`；0x0071 设出冰重量 `manual_ice_weigh(g)`。
- `E_FLOW_MANUAL_MAKE_ICE` → `ice_auto_flow(manual_ice_weigh)` 三阶段：
  1. **读称重/去皮**：`weigh_read_data_ex`，通讯重试最多10次，仍失败判通讯异常退出；杯重>100g 判"称重无杯异常"（`ice_maker_status=0x05`、`ice_weight_no_cup=1`）；杯重≤7g 重试3次判"无杯"（0x03）；**手动模式不先去皮、直接读当前重量当杯重**。
  2. **出冰闭环**：按机型算初始出冰时间（宝路通<120g取17、≥120取29；协厚取8/12，单位0.1s），实时 `当前冰重=总重-杯重`，偏差补偿后 `ice_set_en(补偿时间)` 补出。
  3. **收尾**：达到目标恢复 `ice_maker_status=0x01`、清 `ice_weight_no_cup=0`。
- 0x007E 出冰补偿系数（1~50 钳位，掉电保存到0x08008000）；0x007F 制冰机类型（掉电保存）。

#### F. 热水器（0x0080 加热开始 / 0x0081 加热时间）→ 详细见 5.3。

#### G. 果乳手动出液（0x00A1 种类 / 0x00A2 量）
- 写 0x00A1 触发 `fruilt_milk_manual_contrl()`：**仅 IDLE** 且 type、quantity **都非0** 才执行 `fruit_milk_output_request(E_FRUIT_MILK_SRC_MANUAL, type, quantity)`；返回4（成功出完）后自动把 0x00A1/0x00A2 清0。忙碌时拒绝。

#### H. 机器人点动（0x0030/0x0031/0x0100）
- 0x0030 `手动控制机器人状态`：`robot_base_manual_control(reg_val)`。
- 0x0031 `手动控制机器人到点`：`robot_position_manual_control(reg_val)`。
- 0x0100 `清除机器人到点标志`：`robot_position_manual_clear(reg_val)`。
- 机器人协作走 502 端口 Modbus-TCP，动作采用"置1→机器人完成回读→清0"乒乓机制。

#### I. 水电 / 消毒 / 打印（0x0021/0x0022/0x0024/0x0025/0x002A）
- 0x0021 整机清报警：`contrl_clear_warning()`。
- 0x0022 **手动取消订单制作**：满足取消窗口（`cancel_timeout>=1999`）后 `control_flow_exit()`，清除机器人标志。
- 0x0024 启用水桶位电磁阀：`ctrl_board_manual_switch(reg_val)`（按 `0x0023 water_tank_pos` 选水桶位）。
- 0x0025 紫外线灯：`ctrl_board_out6(reg_val&1)`。
- 0x002A 打印机状态：写 0x02/0x03（打印成功/失败）→ `control_flow_set_print(1)` 放行后续；写 0x01 → `start_print=0`。

#### J. 通用 IO 调试 / 参数配置
- 0x0101 / 0x0102 **强制 IO 线圈写 0 / 写 1**：`output_board_write_signal_coils(reg_val, 0/1)`（联调时强控任意线圈，慎用）。
- 0x003D/0x003E 热/冰杯高度偏移（-100~100 钳位，掉电保存）。
- 0x003F 机器人类型、0x00AA~0x00AF 果乳通道比例系数（10~1000 钳位，掉电保存）。

#### K. OTA / 系统（0x0200~0x0202）
- 0x0200=1 启动 OTA（`IAP_httpd_init`）。
- 0x0201=1 软复位（约 50ms 后 `NVIC_SystemReset`）。
- 0x0202=1 打印软件版本 `g_device_version`。

### 5.3 热水 / 加热任务——详细版

**相关寄存器**：
- 命令：`0x0080 加热开始`、`0x0081 加热时间(分钟,0=默认30)`、`0x0023 启用水桶位`。
- 状态：`0x1082 热水器加水状态`（0=正常/加水完成、0x0003=加水超时未满）、`0x1080 低水位`、`0x1081 高水位`（由X18/X19浮球实时刷新）、`0x1029 异常代码`（bit0=咖啡机抽水异常、bit1=热水器抽水异常）。
- 输出：**Y13 水箱供水电磁阀、Y16 热水器继电器** + 水路电磁阀。

**完整流程**（`water_valve_ctrl` 抽水状态机 + `water_heater_contrl` 加热状态机协作）：

1. 上位机写 `0x0080=1` → `heating_start=1`、`water_heater_fill_stat` 复位为0，进入"热水器需要抽水"分支。
2. 判低水位 `auto_clr_low_water`（X18）：
   - **X18 未检测到水（缺水）** → 打开水箱电磁阀（`ctrl_board_manual_switch` 按 `0x0023` 选水桶位）+ 水路电磁阀 + 开 Y13，进入 `take_water_setup=3` 抽水。
   - **X18 已检测到水** → 不抽水，直接 `heating_flag=1` 开始加热。
3. 抽水状态机（setup=3）：
   - 达到高水位 X19（`auto_clr_high_water=0`）**或**咖啡机水箱不再缺水 → 停抽 → `heating_flag=1` 开始加热、`heating_start` 清0。
   - 中途水桶全没水（`water_tank_sensor=0`）→ 中断并记录已抽水时长（断点续抽）。
   - 抽水超过 **120s**（`coffee_in_water_timeout>119999`）仍未满 → `water_heater_fill_stat=0x0003`、停水报超时。
4. 加热（`water_heater_contrl`）：
   - `heating_flag=1`：若 Y16 关 → 写线圈15=1 打开 Y16，清零计时。
   - `heating_flag=2`：计时，默认（`time_1min_count>29` 约 30 分钟）或按 `0x0081` 指定分钟数 → 到时写线圈15=0 关 Y16。
   - 若 `heating_flag=0` 但 Y16 仍开 → 兜底强制关闭 Y16。
5. **咖啡机抽水**是另一路独立开关（case 0~2）：当咖啡机低水位（`coffee_low_water_level`）缺水时自动开 Y13+水路给咖啡机补水，20s 未到位报 `exception bit0`。
6. **互斥**：热水器与咖啡机共用 Y13/水路电磁阀，任一方在抽水时若检测到另一方也在抽，会主动关掉对方的 Y13，避免串水；且任一方已报抽水异常时不再触发该路抽水。

### 5.4 清洗任务——详细版

#### 5.4.1 奶路清洗（0x0083 写1）→ `milk_pipeline_clean_control()` 五段状态机
- **setup=0（等待触发）**：上位机写 `0x0083=1` 开始。
- **setup=1（向咖啡机发起清洗）**：调 `coffee_set_clean(0x0006)`（奶沫器系统清洗指令）发起，重试≤3次；咖啡机应答 `err_code==0x02` 判定启动成功 → `setup++`；连续3次失败 → 跳 setup=3 并清 `0x0083`。
- **setup=3（等咖啡机回主页）**：`milk_pipeline_clean_timeout>32000`（约32s）后发 `coffee_set_stop()` 让咖啡机退回主页 → `setup++`。
- **setup=4（等咖啡机空闲）**：`coffee_online_stat()==0x01` 判空闲 → `setup++`。
- **default（收尾关阀）**：**Y15（奶路清洗阀，线圈14）连续关3次（每次间隔100ms）**，防关闭信号丢失导致阀未关；随后置 `milk_pipeline_valve_stat(0x1083)=0`、清 `0x0083`、`setup` 归0。
- 状态上报：`0x1083 奶路清洗阀状态(0关/1开)`。

#### 5.4.2 糖浆机清洗（0x0082 或 0x0063~0x65 写1）→ `sugar_clean_enable()`
- 先关 **Y15**（`output_board_write_signal_coils(14,0)`，防止奶路/糖浆清洗交叉串路）。
- 对糖浆机写寄存器 **0x05 先0后1（脉冲触发清洗）**，置 `sugar_run_flag`。
- 清洗状态经 `0x1060` 上报 = **4（清洗中）**；上位机据此轮询。

#### 5.4.3 咖啡机清洗（0x0042 写类型）→ `coffee_set_clean(clean_type)`
- **仅当咖啡机 `sync_id==0x00FF`（空闲）** 才执行：置 `run_flag=0x02`、`coffee_timeout=0`，经 RS485 写咖啡机 **0x200C=清洗类型**。
- 清洗期间咖啡机 `sync_id` 变化，下位机据此刷新 `0x1040` 状态；清洗完成后状态自动复位。

#### 5.4.4 果乳通道清洗（0x00A3~0x00A8 写1启动）→ `fruit_milk_clean_control()`
**通道映射**（每通道独立状态机 `ch_setup[6]`，状态寄存器 `0x10A8~0x10AD`：0停止/1清洗中/2注液中）：
- ch0→0x00A3/0x10A8、ch1→0x00A4/0x10A9、ch2→0x00A5/0x10AA、ch3→0x00A6/0x10AB、ch4→0x00A7/0x10AC、ch5→0x00A8/0x10AD。
- 线圈（IO板3）：ch0 用 A电机/A阀、ch1 用 B电机/B阀；ch2/ch3 用预留 C/D 线圈；ch4/ch5 复用 A/B 线圈但状态寄存器独立。

**状态机（每通道）**：
- **ch_setup=0（等待）**：需 `flow_status==IDLE` 且该通道 `0x00A3~A8=1`；若正在出果乳（`fruit_milk_output_is_busy`）则延迟等待出液完成；**ch0/ch1 互斥**（同一 IO 板3，同一时刻只允许一路进入清洗）→ 通过后置状态=1（清洗中）、`ch_tick=now`。
- **ch_setup=1（开阀出水）**：
  - 每 **200ms** 写一次 IO3 线圈（motor|valve=1），并**每200ms低频主动刷新 IO3 回读**（因为 IO板3 与出餐动作共用一条 RS485，回读会滞后，防假超时/假未开）。
  - ch0/ch1 需**回读确认** A/B 电机+阀都返回开（`fruit_milk_A_motor&A_valve` 等）才算"打开成功"；ch≥2 直接认为打开。
  - **打开超时**：出餐口正在动作时为 **10000ms**，平时 **5000ms**；超时→关阀→循环重试≤3次；仍失败则报"清洗失败"并清该通道触发位。
- **ch_setup=2（清洗计时）**：计时 `FRUIT_MILK_CLEAN_TIME_MS=15000ms`。
- **ch_setup=3（收尾关阀）**：上位机写 `0x00A3~A8=0`（或完成后）进入；关阀（close_retry）、低刷 IO3，完成后清该通道状态=0（停止）。

**与订单/流程的互斥与并发约束**：
- 订单制作前：`E_FLOW_IDLE` 里若 ch0/ch1 状态=清洗中 **或** 触发位=1，则**先等清洗完成再开始新订单**（`wait_fruit_milk_clean_before_order_tick` 1s节流提示）。
- 双通道：只允许任一通道处于"开启/清洗中"（setup 1~3），避免同一 IO 板3 的 RS485 竞争。
- 状态上报路径：`0x10A8~0x10AD`（0 停止 / 1 清洗中 / 2 注液中）供上位机轮询。
