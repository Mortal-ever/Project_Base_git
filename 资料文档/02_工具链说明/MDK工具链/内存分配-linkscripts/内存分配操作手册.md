### 将 FreeRTOS Heap 迁移至 CCM RAM

#### 成功结果：

- `ucHeap = 0x10000000`，32KB 已进入 CCM。
- `RW_CCM` 使用 `0x8000 / 0x10000`，CCM 还剩 32KB。
- 普通 SRAM1 从 `0x19DAC` 降到 `0x11DAC`，准确释放 32KB。
- SRAM1 当前约占 71.4KB，剩余约 40.6KB。
- LwIP、PBUF、ETH RX Pool、DMA 描述符仍在 `0x20000000` SRAM，未误入 CCM。
- 构建结果为 `0 Error(s), 0 Warning(s)`。

#### 实现原理：

1. 在 [FreeRTOSConfig.h](C:/Users/13193/Desktop/MilkTea/Core/Inc/FreeRTOSConfig.h:171) 启用应用自定义堆：
   ```c
   #define configAPPLICATION_ALLOCATED_HEAP 1
   ```

2. 在 [app_task_manager.c](C:/Users/13193/Desktop/MilkTea/Application/UserAPP/Task_Manager/Src/app_task_manager.c:16) 提供 `heap_4.c` 要求的全局 `ucHeap`，并放入独立链接段：
   ```c
   __attribute__((section("CCM_HEAP"), zero_init, aligned(8)))
   uint8_t ucHeap[configTOTAL_HEAP_SIZE];
   ```

3. 新增 [MilkTea_CCM.sct](C:/Users/13193/Desktop/MilkTea/MDK-ARM/MilkTea_CCM.sct:5)，将 `CCM_HEAP` 固定映射到：
   ```text
   0x10000000 - 0x1000FFFF
   ```

4. 在 [MilkTea.uvprojx](C:/Users/13193/Desktop/MilkTea/MDK-ARM/MilkTea.uvprojx:375) 启用这个 scatter 文件。

5. 变更已记录在 [CHANGES.md](C:/Users/13193/Desktop/MilkTea/CHANGES.md:3)。

6. 确认是否将freertos的heap放入ccm中可以根据下面流程进行确认

   - 打开 `MilkTea.map` 文件，按 `Ctrl + F` 搜索下面两个关键字：

   1. **搜索 RW_CCM**
      会看到类似这样的内存区域摘要，它直观地告诉你这块内存被用掉了多少：

      ```
      Execution Region RW_CCM (Base: 0x10000000, Size: 0x00008000, Max: 0x00010000, ABSOLUTE, UNINIT)
      ```

      - 这里的 **Base: 0x10000000** 说明起始地址是 CCM 起点。
      - 这里的 **Size: 0x00008000**（32KB）说明您的 32KB Heap 正好塞进去了，没有多占，也没有少占。

   2. **搜索 app_task_manager.o**
      您会看到编译后的具体目标文件被顺利塞进了这个自定义段：

      ```
      app_task_manager.o(.CCM_HEAP)  0x10000000  0x8000
      ```

      这一行足够说明一切：**段名 .CCM_HEAP，起始地址 0x10000000，占用 0x8000 大小**。

7. **需要注意**：Keil 显示的 `Total RW Size` 仍是约 111.42KB，这是因为它统计所有 RAM 区域总和，迁移不会减少总量，只是从 SRAM 搬到了 CCM。以后 `pvPortMalloc()` 返回的内存可能位于 CCM，禁止直接交给 ETH、UART、SPI 等 DMA；DMA 缓冲区必须继续放在 `0x200xxxxx` SRAM。动态创建的 FreeRTOS 任务栈和 TCB 会随堆自动进入 CCM。
