# 源码教材编写规范

版本：1.0  
日期：2026-09-09  
适用工程：D:/Project_Items/Project_Base

## 1. 目的

本规范把源码说明从文件和符号清单改成可以带着开发者学习的教材。每章先说明设计目标，再用真实源码证明设计如何落地，最后让读者能够沿调用链定位运行结果和故障。

教材顺序固定为：

```text
现实问题 -> 设计决定 -> 层间边界 -> 类型与状态 -> 初始化前置条件
-> 函数执行阶段 -> 端到端调用链 -> 正常/失败路径 -> 调试练习
```

## 2. 事实来源与边界

源码、Keil 工程、GCC CMake 和已确认的硬件/协议资料是事实来源。文档必须区分：

| 状态 | 含义 |
| --- | --- |
| SOURCE | 文件或符号存在 |
| BUILD | 当前 Target 构建清单纳入 |
| RUNTIME | 已确认运行时调用 |
| LEGACY | 保留但不是主路径 |
| UNKNOWN | 证据不足，不能猜测 |

`Application/New_Party/nanoMODBUS` 属于第三方边界；`Application/ProtocolStack/ModbusPort` 属于本工程适配层。

## 3. 每章必须回答的问题

1. 本模块解决什么现实问题？
2. 它属于公共层还是 Target 私有层？谁拥有它？
3. 文件和符号在 Keil/GCC 中是否纳入？
4. 初始化前必须完成什么？
5. 宏、枚举、结构体和函数表达什么？
6. 函数体按什么阶段执行？
7. 成功、超时、协议异常、传输错误和取消如何区分？
8. 状态由谁写入、谁读取，生命周期和并发边界是什么？
9. 日志、断点和观察变量在哪里？
10. 读者完成什么练习？

## 4. 说明规则

重要枚举提供“数值、产生者、处理者、动作、终态”表；重要结构体提供“字段、初始化、写入者、读取者、生命周期、并发/指针约束”表；函数按参数校验、资源准备、协议调用、响应解析、状态提交、结果映射分段说明。不得逐行翻译，也不得用一句“发送并解析”替代关键阶段。

## 5. 场景和验收

每个模块至少配一个真实场景，写出触发条件、入口任务、消息变化、下层调用、协议帧或 GPIO 行为、完成条件、错误出口、日志和断点。读者必须能找到初始化入口、追踪枚举到处理分支、说明结构体字段所有者、定位超时层级，并判断修改文件影响哪些 Target。无法确认的内容标记 UNKNOWN。
