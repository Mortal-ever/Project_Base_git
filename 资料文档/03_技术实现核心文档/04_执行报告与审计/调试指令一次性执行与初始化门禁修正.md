# 调试指令一次性执行与初始化门禁修正

日期：2026-09-07

IO 输出调试和机器人手动调试命令属于一次性操作：上位机写入一次，系统执行一次，命令完成后退出，不参与自动业务的输出所有权互斥，也不保持 Manual reservation。调试命令只在初始化完成后接受；硬件、软件、残杯、机器人回原点和出餐门关门到位任一项未完成时，返回设备故障并输出 `DEBUG_COMMAND_REJECTED_NOT_INITIALIZED`。

本次修正同步 Coffee2Open 与 Coffee3Close：

- 520（板载输出调试）和 521（外部 16 路输出调试）不再检查 automatic、maintenance 或 OTA 所有权。
- 板载输出使用一次完整 mask 写入。输出点逐点写入时不再使用业务层的 DO1/DO2 互锁，因此 `0x000F` 可以按调试请求同时拉高前四路；该接口只用于初始化完成后的硬件测试。
- 外部输出仍提交一个 `IO_WRITE_MASK` 命令，队列完成后即结束，不形成持续控制状态。
- 初始化完成后状态读取、正常 Workflow 输出和维护流程仍使用原有业务接口。
- 调试命令在初始化未完成时被拒绝，拒绝只针对调试命令，不影响初始化自身的系统动作。

当前日志示例：

```text
[0000WARN][C3Server:MBTcpServer] IO_DEBUG_REJECTED_NOT_INITIALIZED result=-1001
[0000INFO][C3Server:MBTcpServer] LOCAL_IO_DEBUG_OUTPUT_SET=0x000F
```

Keil ARMCC V5 Coffee2Open 与 Coffee3Close 均构建通过，0 Error、0 Warning；本次未烧录，外部 IO 和板载硬件需上板验证。
