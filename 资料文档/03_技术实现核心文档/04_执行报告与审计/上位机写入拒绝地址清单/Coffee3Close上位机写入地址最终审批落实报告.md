# Coffee3Close 上位机写入地址最终审批落实报告

## 1. 落实结论

最终审批的地址边界已落入 Coffee3Close 源码。未修改 Coffee2Open，也未新增配置模块、配置结构版本或 Flash 分区。

## 2. 配置持久化

果乳比例系数继续使用原有 Coffee3 私有配置模块和 sector 2：

- 唯一配置类型：`Coffee3Config_t`；
- 唯一格式标记：`COFFEE3_CONFIG_MARK`；
- 原存储位掩码字段保留；
- 新增六个 `uint32_t` 果乳系数字段；
- 默认值100，有效范围10~1000；
- FC06或FC16修改任意一路时，先形成完整配置并一次擦写整份结构；
- 同值写入不擦 Flash；
- 保存失败不发布寄存器镜像，返回服务器设备故障；
- 旧两字段记录中的后续Flash字为 `0xFFFFFFFF`，上电保留原存储位掩码，将六路系数补成100并用同一标记回写。

没有新增 `Coffee3ConfigV2`、第二份配置结构、第二个配置地址或追加记录机制。

## 3. 地址行为

| 地址 | 最终行为 |
| --- | --- |
| `0x0032` | 可读写；取消只读拒绝。上位机写入更新命令镜像，Workflow与机器人仍可后续更新该事务字段 |
| `0x003F` | 接受全部16位值并保留镜像；Coffee3仍固定使用越疆驱动 |
| `0x0041` | 按Coffee1语义取 `bit0`，直接控制板载 `DO4_COFFEE_WATER_TANK_SUPPLY_PUMP`；属于一次性调试直控，后续自动补水可以覆盖其状态 |
| `0x007F` | 接受写入但不切换制冰机驱动；日志明确为制冰机类型，不再错误描述为M50 |
| `0x00AA/0x00AB` | 持久化并分别作为果乳A/B的 `ms/ml` 系数，实际参与出液运行时间计算 |
| `0x00AC~0x00AF` | 同样持久化；当前没有物理通道，不产生IO动作，供未来扩展 |

首轮审批中要求开放的 `0x001F、0x0023~0x0025、0x002A、0x003D、0x003E、0x0043、0x004E、0x004F、0x007E、0x007F` 也已进入写入合同。没有实际设备或业务消费者的地址接受并保留镜像，同时打印“已接收但未执行”的具体原因。

继续拒绝的出餐升降、风扇、灯带、第二出餐口、旧IO调试空洞、状态只读区和未定义保留地址没有放开。

## 4. 日志

- `0x0041`：打印请求值和DO4最终目标值。
- `0x0032`、`0x0023`：打印正常接受的信息，不使用误导性的拒绝或设备故障日志。
- 未安装功能：打印 `address`、`value` 和未执行原因，但Modbus写入成功。
- 果乳系数：打印通道、请求值、钳位后的生效值及物理通道是否安装。
- 真正非法的地址和值继续打印 `Command rejected` 并返回对应Modbus异常。

## 5. 验证结果

| 验证项 | 结果 |
| --- | --- |
| GCC Coffee3Close Debug | 通过；FLASH 189600B，RAM 103360B，CCMRAM 41192B |
| Keil Coffee3Close / ARMCC V5.06u7 | 通过；Code 211652B、RO-data 9012B、RW-data 596B、ZI-data 144356B；0 Error、0 Warning |
| Flash地址 | 仍为sector 2 `0x08008000`，未改变OTA、网页或机器人端口区 |
| 硬件实测 | 未执行；需上板验证DO4、断电系数保持和A/B实际出液时间 |

## 6. 上板验收建议

1. FC06分别写 `0x0032` 的0、1、2及其他16位值，FC03读回一致；确认机器人/Workflow后续写回仍可覆盖。
2. FC06写 `0x0041=1`，确认DO4开启；写0确认关闭；随后触发自动补水，确认自动流程仍可控制DO4。
3. 写 `0x00AA=50、0x00AB=150`，重启后读回保持；以相同出液量验证A/B运行时间分别按系数变化。
4. 写 `0x00AC~0x00AF` 后重启读回保持，同时确认不会访问不存在的IO通道。
5. 分别写审批开放但未安装的地址，确认Modbus成功且日志明确说明没有动作。
6. 验证 `0x0091、0x0093、0x0094、0x0099~0x009C` 仍返回拒绝。
