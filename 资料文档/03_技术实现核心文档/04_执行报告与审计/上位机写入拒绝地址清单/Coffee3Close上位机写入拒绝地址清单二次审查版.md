# Coffee3Close 上位机写入拒绝地址清单（二次审查版）

## 1. 文档目的与本轮边界

本文吸收《Coffee3Close上位机写入拒绝地址清单-审批.md》的逐项审批意见，并重新核对 Coffee1 `coffee_close_v2.8.29_IOPage` 的实际源码。

本版已完成最终审批。固件按本文边界实施，具体结果见
《Coffee3Close上位机写入地址最终审批落实报告.md》。

本文把写入结果分成四类，避免把“Modbus 写成功”误认为“设备已执行”：

1. **接受并执行**：值校验通过后触发 Coffee3Close 的真实功能。
2. **接受并保存**：更新寄存器或持久化配置，但当前硬件可能不消费该值。
3. **接受但不动作**：为了上位机兼容而应答成功，同时打印明确的未安装/未实现日志。
4. **拒绝**：返回 Modbus 异常，并打印地址、数值及拒绝原因。

## 2. Coffee1 二次调研事实

### 2.1 `0x0041` 咖啡机进水泵

Coffee1 在 `modbus/tcp_server.c` 的 `case 0x41` 中调用：

```c
ctrl_board_out5(reg_val & 0x01);
```

结论：Coffee1 **已实现实际输出控制**，只取写入值最低位，没有附加液位联锁或独立状态机门禁。

Coffee3Close 已安装咖啡机水箱供水泵，对应板载 `DO4_COFFEE_WATER_TANK_SUPPLY_PUMP`，自动补水流程也会使用 DO4。因此建议：

- 开放 `0x0041`，`bit0=0` 关闭、`bit0=1` 开启；
- 作为工程调试的一次性直接输出，不取得 DO4 的长期所有权；
- 后续自动补水流程可以再次改写 DO4；
- 每次命令打印“接受、目标状态、DO4、调试直控”日志；
- 不打印“未安装”，因为 Coffee3Close 实际具备该泵。

### 2.2 `0x0043` 咖啡制作中可取餐时间

Coffee1 的寄存器结构把 `0x0043~0x006F` 定义为保留区，Coffee1 TCP Server 中不存在 `case 0x43`，业务流程中也未发现对该地址的消费者。

结论：不能宣称该功能从 Coffee1 继承。按审批意图建议开放为**兼容接收但不动作**：保存当前寄存器镜像，打印“参数尚未实现，不参与 Coffee3Close 业务时序”。不写 Flash，不改变取餐或订单流程。

### 2.3 `0x00AA~0x00AF` 果乳通道比例系数

Coffee1 对六个地址均有完整实现：

- 默认值为 `100`；
- 有效范围为 `10~1000`，越界值会被钳位；
- 六个值均写入 `machine_type` Flash 配置；
- 实际果乳执行时按通道读取对应系数参与运行时长计算。

Coffee3Close 当前只有果乳 A/B 两个物理通道，现用固定值 `COFFEE3_FRUIT_MILK_MS_PER_ML=100` 计算泵运行时间。因此建议不是简单空操作，而是：

- `0x00AA/0x00AB`：接受 `10~1000`，写配置并实际替代 A/B 两路固定系数；
- `0x00AC~0x00AF`：同样接受 `10~1000` 并保存在配置中，为后续通道扩展保留，但当前不驱动任何输出；
- 越界处理建议与 Coffee1 一致，钳位到边界并打印原值和生效值；
- Flash 保存失败时返回服务器设备故障，不能回报成功；
- 只有值实际变化时才擦写配置区。

这比“全部接收但不使用”更符合协议语义，也保留了 Coffee1 已验证的标定能力。

### 2.4 其他 Coffee1 配置项事实修正

| `0x0024` | 直接调用水桶电磁阀选择函数 | Coffee3 无同构四路水桶阀，按审批接受全部值但不动作，明确打印兼容日志 |

| `0x003F` | 机器人类型写入 Flash | Coffee3 固定越疆机器人，建议接受全部值但仅镜像；日志说明固定越疆、不切换驱动 |

### 3.1 对 `0x003D/0x003E/0x003F` 的补充建议

审批意见明确要求前两项开放。为保持上位机批量参数写入兼容，建议 `0x003F` 也采用“全值接受、驱动固定”的同类策略，不再仅接受 0/1。否则跨 `0x003D~0x003F` 的 FC16 仍可能因为最后一个地址导致整帧失败。

## 5. 保留地址的最终建议

对没有协议定义、没有审批用途的保留地址继续拒绝，避免“任何地址都写成功”掩盖上位机地址错误：

- `0x0020、0x0026~0x0029、0x002B~0x002F`
- `0x0034~0x003C`
- `0x0044~0x0046、0x0048~0x004D`
- `0x0051~0x005F`
- `0x0064~0x006F`
- `0x0072~0x007D`
- `0x0087~0x008F`
- `0x0090、0x0095~0x0098`
- `0x00A0、0x00A9`
- `0x0203~0x0207`

订单固定长度 FC16 中已有的保留填充规则维持现状：`0x000F~0x0012`、`0x0015~0x0019` 只允许值0随合法订单帧通过，不开放为独立命令。

## 7. FC06、FC16与日志规则

1. FC06 与 FC16 必须走同一地址和值域校验，不允许行为分叉。
2. FC16 保持整帧原子预校验：任一地址真正非法时，整帧拒绝且不产生部分动作。
3. “接受但不动作”地址在 FC16 中不应导致整帧失败。
4. 对未安装/未实现项必须明确打印：`address`、`value`、功能名称和“不动作”原因。
5. 对真实动作必须打印接受与执行结果，不能只打印寄存器写成功。
6. 高频上位机重复写相同兼容值时应抑制重复日志；非零触发命令或值发生变化时必须打印。
7. 所有拒绝日志继续使用明确文本，例如：

```text
[F123WARN][C3Server:MBTcpServer] Command rejected: address=145 value=2; outlet lift is not installed
```

“接受但不动作”不能使用 `rejected`，建议格式：

```text
[F123WARN][C3Server:MBTcpServer] Command accepted without action: address=37 value=1; UV lamp is not installed
```

## 8. 最终审批实施范围

最终审批已经确认并实施：

1. 扩充 Coffee3 Server 地址白名单及统一 FC06/FC16 提交处理。
2. 增加 `0x0041 -> DO4` 一次性调试控制，并验证不会取得长期输出所有权。
3. 将 `0x00AA~0x00AF` 纳入 Coffee3 配置结构，默认100、范围10~1000；A/B实际参与运行时长换算。
4. 为兼容接收但不动作的地址增加可读镜像和准确日志，不伪造设备状态。
5. 保持本文列出的拒绝地址、只读区和运行时门禁不变。
6. 完成 Keil ARMCC V5 与 GCC 双工具链构建，并形成寄存器级测试矩阵。

## 9. 最终审批结论

1. `0x0041` 按 Coffee1 语义直接控制 Coffee3 板载 DO4。
2. `0x00AA~0x00AF` 全部进入唯一 `Coffee3Config_t` 持久化；A/B实际生效，3~6为未来扩展保存。
3. `0x003F` 接受全部16位值，但 Coffee3 固定使用越疆驱动。
4. `0x0032` 为可读写地址，不进行只读保护。
5. 配置结构不新增V1/V2并行类型，统一使用 `Coffee3Config_t` 和 `COFFEE3_CONFIG_MARK`。
