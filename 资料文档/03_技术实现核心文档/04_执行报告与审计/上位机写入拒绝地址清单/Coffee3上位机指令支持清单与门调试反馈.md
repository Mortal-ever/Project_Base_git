# Coffee3Close上位机指令支持清单与门调试反馈

日期：2026-09-14。

## 修正原因

此前命令区0x0000～0x00AF只做范围检查，即使没有动作分发也保存值并返回成功。145升降等指令因此表现为“写入成功、无动作、无日志”。现在先按Coffee3Close的明确支持清单检查，未知地址拒绝，后续新增功能必须同时补充支持清单和执行处理。

拒绝示例：

```text
[F123WARN][C3Server:MBTcpServer] Command rejected: address=145 value=2; outlet lift is not installed
```

## 写入约定

- 未支持的地址返回Modbus异常02，打印十进制地址、值和原因；拒绝前不写镜像、不调用设备。
- 已支持动作的非法值返回异常03并打印原因。
- 门请求初始化未完成或待处理槽已占用，返回异常04并打印原因；当前协议栈没有新增异常码。
- FC06、FC16共用检查。FC16先校验整个请求，遇到不支持项报告首个失败地址，整包不提交；不承诺跨设备执行的事务回滚。
- FC03读取不触发调试，也不重复打印拒绝。保留现有只读状态和预留地址读取能力，读地址存在不代表支持写指令。
- 明确保留订单批量包中零值占位：6、0x000F～0x0012、0x0015～0x001F中非配置项。仅限订单范围内多寄存器写且值为0，不代表新增功能。0x001A仍是持久化配置，按现有规则保存。
- 机器人0x0033写回、0x000A清零、0x001A配置、OTA 0x0200～0x0202、IO调试520/521保持明确支持。

## 出餐机构

| 十进制 | 十六进制 | Coffee3Close行为 |
| --- | --- | --- |
| 145 | 0x0091 | 拒绝：未安装出餐平台升降机构 |
| 146 | 0x0092 | 1开门、2关门；0不触发动作 |
| 147/148 | 0x0093/0x0094 | 拒绝：未支持风扇/灯带 |
| 153～156 | 0x0099～0x009C | 拒绝：未安装出餐口2 |
| 157 | 0x009D | 1停止当前门动作；0不触发动作 |

开门使用DO2下降、DI2下限位；关门使用DO1上升、DI1上限位。Server提交一次请求，Workflow原有门控负责执行与5秒超时，不在Server线程直接驱动门。动作开始、到位、已在目标位置、失败和停止均由执行者说明；手动动作使用F123，正常业务保留原订单标识。没有新增线程或动态分配。

## 其他明确支持的写入地址

以下均为十六进制，具体值仍服从各处理器：

- 订单/握手：0x0000～0x000E（0x0006仅零值占位）、0x0013、0x0014；配置0x001A；清报警0x0021、取消0x0022。
- 机器人：0x0030本体控制、0x0031已安装动作位置、0x0033出餐选位写回；0x0032仍禁止外部写。
- 咖啡机：0x0040制作、0x0042清洗、0x0047取消。
- 杯盖：0x0050；糖浆：0x0060～0x0063；冰：0x0070、0x0071。
- 热水及清洗：0x0080～0x0083。
- 果乳：0x00A1～0x00A4。
- OTA和版本：0x0200～0x0202；IO输出调试：0x0208、0x0209。

支持表位于`coffee3_server.c`的`prvValidateHostWrite()`。添加地址前需实现执行入口、参数检查、接受/拒绝和完成/失败反馈；不能只增加一个case就宣称支持。

## 上板检查

1. 写145=2、148=1、154=1，观察明确WARN及异常02，确认无输出变化。
2. 初始化完成后写146=1，DO2动作；触发DI2后停止并打印完成；146=2对应DO1/DI1。
3. 不触发目标限位，5秒后输出关闭且打印超时；双限位同时有效应打印冲突。
4. 动作中写157=1，确认两路输出关闭、该次门运动结束。
5. FC16单寄存器写146同样生效；批量包含未知地址时整包拒绝。
6. 回归订单包、0x001A配置、机器人0x0033清零读回、520/521、OTA已支持写入。

以上是验收步骤，不表示已上板通过。
