# Coffee3Close地址0x0023水桶位兼容调研报告

## 1 结论

当前Coffee3Close确实不支持十进制35（0x0023）的写入。`coffee3_server.c`的上位机写白名单没有包含0x0023，因此无论写0还是写1都返回“非法数据地址”，并打印：

```text
[F123WARN][C3Server:MBTcpServer] Command rejected: address=35 value=0; command is not supported by Coffee3Close
```

这不是X4水桶传感器故障，也不是水路任务失败，而是上位机协议兼容层的明确拒绝。根据最新业务要求，Coffee3Close后续应开放0x0023定义的全部水桶位：0x0000、0x0001、0x0010、0x0100和0x1000均接受，不因当前BOM只安装一个水桶而拒绝。X4仍是当前已接入水桶1的实时事实；未接入的水桶位只保留配置意图，不虚构传感器或执行输出。

## 2 日志事件还原

日志中0x0023拒绝在机器人启动、残杯检查和机器人动作期间持续出现，且值始终为0。这说明有TCP客户端在周期写入包含地址35的数据，而不是一次性手动命令。

Coffee3服务端在FC16提交前会校验整个写入范围。因此，如果上位机批量写入的帧跨过0x0023，地址35被拒绝会使整个FC16帧失败，同一帧内其他已支持的参数也不会提交。所以该问题是上位机兼容阻断，不只是日志重复。

日志中机器人动作可正常接受和完成，这也排除了0x0023拒绝是机器人通信失败的可能。

## 3 协议定义

当前《咖啡售卖机下位机通信协议》对0x0023的定义为“启用水桶位”：

| 值 | 协议含义 |
| --- | --- |
| 0x0000 | 由下位机自动选择 |
| 0x0001 | 水桶位1 |
| 0x0010 | 水桶位2 |
| 0x0100 | 水桶位3 |
| 0x1000 | 水桶位4 |

该字段是选源配置，不是水桶当前有水或无水的状态。协议表中的“0x0000 - 0x1111”应结合枚举值理解，不应直接视为任意16位数值都合法。

## 4 Coffee1事实实现

Coffee1保留了0x0023字段 `water_tank_pos`，并将其与实时水桶传感器位图 `water_tank_sensor`分开。其处理规则是：

1. 0x0023为0时，按实时水桶传感器位图自动选择有水的桶位。
2. 0x0023非0时，作为首选水桶位；当首选位无水时，按固定顺序切换到其他有水桶位。
3. `ctrl_board_manual_switch()`最终控制四路水桶阀，且始终参考实时传感器位图，不会因为0x0023的配置值就强行使用缺水桶。
4. Coffee1的0x1021发布四个水桶传感器状态，0x1022发布四个水阀状态。这两者与0x0023配置形成“选择意图—实时水源—执行阀状态”三层关系。

Coffee1还在咖啡机水箱补水和热水桶补水中复用该选桶逻辑；无可用水源时停止阀和泵，并进入相应异常处理。

## 5 Coffee3Close物理边界

根据Coffee3Close配置说明、3D分布图和水路示意图，当前Target只配置一个纯净水桶水源：

- X4是水桶1的实时低液位信号；
- DO4用于咖啡机水箱补水；
- DO3用于热水桶供水；
- 热水桶再为果乳、奶路等清洗分支提供清洗水；
- 咖啡机通过自身协议执行咖啡管路清洗。

Coffee3Close的IO清单中没有Coffee1的四路水桶切换阀，因此不能照搬Coffee1的 `ctrl_board_manual_switch()`，也不应为了协议兼容虚构多水桶执行动作。

## 6 Coffee3Close已有水源逻辑

Coffee3Close已将X4索引定义为 `COFFEE3_EXTERNAL_DI_PURE_WATER_LOW`，并已在业务中使用：

- 初始化后X4丢失时置水源告警；
- 当前订单不强制中断，完成后禁止下一单；
- X4恢复后，结合清警重新开放订单；
- 热水任务运行中X4无效或IO数据无效时，请求停止供水和加热流程。

不足是0x0023还没有进入Coffee3的协议兼容层，且水源使用意图没有独立字段。目前系统只能根据X4判断水源，无法正常接收上位机协议中的选桶配置。

## 7 建议的最小落地方案

### 7.1 可接受值

| 写入值 | Coffee3Close处理 | 理由 |
| --- | --- | --- |
| 0x0000 | 接受，由下位机自动选择 | 协议默认值 |
| 0x0001 | 接受，水桶位1 | 当前已安装 |
| 0x0010 | 接受，水桶位2 | 业务要求预留 |
| 0x0100 | 接受，水桶位3 | 业务要求预留 |
| 0x1000 | 接受，水桶位4 | 业务要求预留 |
| 协议未定义的组合或其他值 | 待审批 | “0x0000-0x1111”与枚举说明存在歧义 |

0x0023只存储选择意图。真正执行DO3或DO4前，仍必须检查IO快照有效且X4允许供水。X4不允许时，无论0x0023是0还是1都不能启动补水。

### 7.2 服务端处理

1. 在Coffee3上位机写白名单增加0x0023，至少使0、1、0x10、0x100和0x1000全部通过。
2. FC06和FC16均使用同一校验；FC16中0x0023=0不再使整帧失败。
3. 仅当配置值变化时打印一条日志，不对周期写入的相同值重复打印。
4. 未安装的水桶位不拒绝，保留配置值供后续扩展；不因配置值虚构当前IO状态。
5. 上位机读回0x0023时返回当前接受值，不用X4实时状态覆盖。

### 7.3 是否持久化

本轮建议不将持久化作为开放0x0023的前置条件。Coffee3只有一个固定水桶，上电默认0已能唯一映射到水桶1。如果产品要求上电后读回上次写入的1，再将该字段加入现有Coffee3配置结构，不单独新建Flash区或状态机。

## 8 后续实施验收

1. FC06分别写0、1、0x0010、0x0100和0x1000，期望全部成功并可读回。
2. FC16写入一个跨过0x0023的参数块，其0x0023=0，确认整帧成功且其他字段完整提交。
3. 反复写入相同值0，确认无重复WARN日志。
4. X4不允许时请求热水和咖啡机补水，确认DO3、DO4保持关闭，并有明确缺水日志。
5. X4在订单中丢失，确认当前订单正常收尾，完成后不接收下一单。
6. X4恢复并执行清警后，确认重新开放订单。
