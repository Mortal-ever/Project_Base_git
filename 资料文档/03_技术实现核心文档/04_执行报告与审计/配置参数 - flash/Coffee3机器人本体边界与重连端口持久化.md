# Coffee3 机器人本体边界与重连端口持久化

日期：2026-09-10。实现对象：当前 Coffee3Close；Coffee2Open 回归验证公共 Transport 兼容性，未迁移其机器人业务。

## 已确认的边界

越疆机器人有两个不同层次：厂商本体控制程序，及工程自行开发的 3100～3139 协议程序。本体开始、停止、使能、清报警、暂停、拖拽、模式切换（本工程动作100～109）只要求 TCP 已连接，不要求整机初始化完成、机器人 RUNNING 或协议3100有效。否则“停止→不能发开始→永远无法就绪”会形成循环依赖。

自定义协议动作要求成功清除本次会话的3100之后，重新读取3100=1、本体RUNNING=1、ENABLED=1且无报警。3110启动信号属于自定义程序，不能绕过该检查。3100清零本身是建立会话的握手，不受程序RUNNING条件约束。

Server 在 coffee3_server.c 的 prvSubmitManual 区分这两种准入。Robot owner 在TCP连接后优先处理队首本体动作，即使协议就绪/事务恢复尚未完成；prvExecute 对本体动作直接发送既有下降/上升沿，不再先读取整套业务协议状态。既有业务事务不会因为本体命令成功而被伪造为完成。本体命令的Modbus写失败仍返回真实错误；“允许下发”不等于强制报告成功。

每次新TCP连接在 session probe 中用 FC05 清3100，清零成功后才建立协议会话，缓存3100同时置0。之后的实际读取才可以建立READY；不会要求读到零，因为机器人可能在清零应答后立即重置为1。清零失败会返回连接恢复流程。

## 源端口与Flash

Coffee1 modbus/tcp_client.c 已有 tcp_bind 和本地端口递增、成功后保存下一端口的处理。本次沿用显式绑定思路，改为连接前提交记录，以覆盖连接成功后立即断电的情况。

| 分区 | 地址范围（含末地址） | 使用者 |
| --- | --- | --- |
| Bootloader | 0x08000000～0x08003FFF | Bootloader |
| OTA元数据 | 0x08004000～0x08007FFF | OTA/Bootloader |
| 机器配置预留 | 0x08008000～0x0800BFFF | 本次不使用 |
| 应用 | 0x0800C000～0x0805FFFF | Keil/GCC应用链接区 |
| OTA暂存 | 0x08060000～0x080BFFFF | OTA扇区7～9 |
| 源端口日志A | 0x080C0000～0x080DFFFF | 扇区10 |
| 源端口日志B | 0x080E0000～0x080FFFFF | 扇区11 |

事实源：coffee3_ota.h/.c、Coffee3Close_CCM.sct、GCC OTA链接脚本、外部Bootloader V4.0的bootloader.h/.c；当前工程搜索未发现扇区10/11其他占用。今后分区变更必须保留这两个区域；整片擦除或其他固件使用这两区会丢失计数。代码读取Flash容量寄存器，非1024KB拒绝使用这些地址，不以日志字符串推测物理容量。

源端口49152～65535，目的端口仍502；序号每次增加，映射为49152 + ((sequence - 1) % 16384)。不会对“基准+65535”直接进行uint16截断而落入0或监听服务端口。每16384次预留后回绕49152；机器人长期不重启且记忆超过这一范围时仍可能复用，不能宣称永久不重复。

每条16字节：magic、sequence、反码、最后写入的commit。连接前完成写入与回读；写入失败不发送SYN。绑定失败也消耗已预留端口，下次继续递增。每区8192条，按追加方式编程；区满后擦除另一区，原区保留最近有效记录。扫描只接受校验及commit正确记录，跳过中断写入；序号按32位差值比较以支持回绕。

掉电结果：未commit不发连接，可重试该尚未用过的端口；commit后掉电将跳过该端口；切区擦除中掉电可从原区恢复。不得每次连接擦除同一Flash字。Flash编程期间暂停任务调度以避免与task上下文OTA写入交错，OTA活动时推迟连接。没有增加任务、队列或堆分配。

STM32F407同Bank擦写会影响取指与实时性，尤其每8192条的128KB擦除可能产生明显暂停。本次未通过实机测量擦除时间、看门狗余量或掉电故障注入；双区记录保障数据提交顺序，不等同于无实时性影响。

公共Transport只增加可选的源端口预留回调，由产品在Create后设置；回调NULL保持原有自动源端口，公共层不引用Coffee3或Flash地址。配置结构不变，现有用户初始化方式兼容。TcpClientSession探测接口文档明确允许会话握手初始化、不允许物理动作。

## 验证与实机验收

Coffee3Close：Keil ARMCC5、GCC Debug构建通过。Coffee2Open：公共TCP上下文改动回归Keil/GCC。map显示应用仍在0x0800C000起始的336KB区域，Ethernet DMA描述符仍在0x200xxxxx SRAM。本次未烧录。

1. 本体STOPPED、TCP已连接：下发开始必须收到实际写命令，不应出现DEVICE_NOT_READY拒绝。
2. 本体停止时下发3100～3139业务动作：拒绝或保持未就绪，不能误报执行成功。
3. 模拟器预置3100=1后重连：抓包先看到3100清0；不再重新置1时READY保持0；重新置1且本体运行才就绪。
4. 连续失败重连和MCU重启：抓包源端口连续变化，目的端口始终502；日志打印预留端口和序号。
5. 断电测试覆盖四个记录写入阶段及切区擦除；再次启动不能复用已经发过SYN的端口（未完成整片擦除、未发生规定范围回绕的前提下）。
6. OTA期间重连推迟；OTA更新后端口记录仍在；双区满/源端口回绕和硬件Flash写失败须专项测试。

源端口复用是用户现场确认的机器人行为；本次软件绑定实现尚不能独立证明所有历史重连失败均由该原因引起，应以SYN/SYN-ACK、实际源端口和native_error联合验收。
