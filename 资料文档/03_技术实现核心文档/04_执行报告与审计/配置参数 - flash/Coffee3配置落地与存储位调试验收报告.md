# Coffee3配置落地与存储位调试验收报告

日期：2026-09-11。依据《上位机可配置参数调研与单地址Flash落地审批方案》。本轮实现 Coffee3Close，未改变 Coffee2Open 业务，未烧录。

## 1. 已实现的结果

| 上位机操作（协议地址，不是4xxxx显示编号） | 行为 |
| --- | --- |
| FC03读0x001A（十进制26） | 返回完整16位配置，首次有效默认值0x0003 |
| FC06或FC16写0x001A | 0x0000～0xFFFF全部允许，保存成功才更新读回值并响应成功 |
| 写0x0031（十进制49），值21/0x0015 | 手动放存储位1，使用既有PUT_STORAGE动作及参数1 |
| 写0x0031，值22/0x0016 | 手动放存储位2，使用同一动作及参数2 |
| 写0x0031，值23/0x0017及后续未定义位置 | 仍打印MANUAL_ROBOT_POSITION_UNSUPPORTED，不投递机器人动作 |

这里的“不支持”沿用现有应用命令处理：寄存器写响应不等于机器人动作成功，不能仅凭FC06回显判断执行结果。

手动放1/2不由配置掩码禁止；它是物理点位调试，仍保留原机器人在线/就绪、任务投递和协议握手检查。机器人未就绪时仍可能拒绝，但不再因为21/22缺少映射而拒绝。

机器人执行器原本已经支持PUT_STORAGE且限制参数1～2。本轮补的是上位机入口；执行器仍在动作发出前通过`vCoffee3ServerSelectStorage()`发布0x0032选位，不另写一套机器人协议。

## 2. 配置含义与运行边界

- RAM维护`Coffee3Config_t`；Flash只保存标记和存储位开放掩码。
- 0x001A原样保存/读回；自动选位使用`mask & 0x0003`，并检查对应X1/X2无杯。
- 默认0x0003：开放物理存储位1和2；0x0001只开放1；0x0002只开放2；0关闭自动存储选位。
- 0xFFFF是合法配置，不当成空白Flash；有效物理位仍然只有1/2。
- 选位遵守原先先1后2的顺序。配置改变不会重选已经被当前流程选定的目的地；后续选位读取新配置。
- 残杯流程也经过现有选位函数，因而遵守开放掩码，选不到存储位时保留既有出餐口回退逻辑。
- 配置写本身不触发动作，也不借此重新尝试挂起的订单；同一FC16包确实包含其他命令时，在配置保存成功后保留原命令分发。
- FC16没有增加“只能写一个寄存器”限制。包范围越界或覆盖只读0x0032，先拒绝整包，不擦写配置。

## 3. Flash布局与提交过程

| 地址/区域 | 本轮用途或保护边界 |
| --- | --- |
| 0x08008000 | 32位有效标记0x43334331，表示Coffee3配置V1 |
| 0x08008004 | 32位字段存放16位mask，高16位必须为0 |
| sector2：0x08008000～0x0800BFFF | 配置独占擦除扇区，当前有效内容8字节 |
| sector1、应用从0x0800C000开始、OTA暂存、sector10/11端口记录 | 不修改其地址、内容格式或擦写业务 |

Keil `ScatterFiles/Coffee3Close_CCM.sct` 与GCC使用的OTA链接脚本均让应用从0x0800C000开始，长度0x54000。HTTP页面仍是`app_ota_http.c`中的应用只读常量，不搬移到配置扇区。

启动在设备/工作流/Server初始化前加载一次配置。标记及字段合法则直接读取，不擦写；空白或不认识的格式记录WARN，保存默认0x03；保存失败通过启动早期串口提示并阻止应用任务创建，不能宣称初始化成功。

写配置流程：暂停任务调度以串行访问Flash → 检查OTA是否占用 → 同值且已持久化则跳过擦写 → 擦sector2 → 写配置字段并读回 → 最后写标记 → 锁Flash并完整读回 → 成功后发布RAM。

失败返回Modbus异常04，记录mask与结果；不更新上位机寄存器镜像。RAM保留旧值，但标记其“不再确认已经落盘”，下次即使写旧值也会重新保存。OTA HTTP活动时，仍采用现有Server拒绝路径；底层OTA占用导致的保存失败映射为异常04，未改nanoMODBUS枚举或协议栈。

Flash串行方式沿用当前机器人端口写入者的调度暂停约定；中断保持开启，无新增任务、定时保存或动态内存。公共读写函数自身不负责跨任务锁，其他Target接入时必须安排相同的Flash写入协调。

**已接受限制**：单副本擦除后掉电可能丢失配置，下次恢复默认0x03；标记最后写不等于备份。没有CRC、历史记录或双副本，不承诺检测任意位翻转。整片擦除也会丢失配置；下载请只擦应用所需扇区。sector2不能混存其他需要保留的数据。

擦除是同步操作，会暂停任务调度，不能宣称不影响实时性；上板需测量写配置时通信延迟及运动/IO任务响应。不需要为此增加频率限制，但建议配置操作在设备空闲时执行。

## 6. 上板验收顺序（尚未执行）

1. 下载Coffee3Close新固件；不要整片擦除。空白配置首次启动读0x001A应为3；确认启动日志无配置初始化失败。
2. 机器人协议已就绪、动作空间确认无障碍后，向0x0031依次写21、22。各自等待前一动作结束；应分别发布0x0032=1/2并执行放杯，不再出现POSITION_UNSUPPORTED。
3. 写23、24、28，应保留不支持日志且不发送放杯动作。不要将十进制21误填为十六进制0x21。
4. FC06对0x001A分别写0、1、2、3、0xFFFF，逐次读回并重启确认保存；0和0xFFFF重启后不应被恢复为默认。
5. FC16从0x001A起写两个寄存器（第二个用既有无动作值0），确认配置保存和读回，不因数量2被拒绝，不触发订单；自动选位分别验证mask1/2/0/FFFF。
6. 配置为0时手动21/22仍不因掩码拒绝；自动存储不能选择关闭位。最后将配置恢复3。
7. 测试Flash写失败、写中掉电和OTA并发：不能先执行包内动作或假报保存成功；允许掉电后默认恢复3。核对HTTP页面和端口记录未被覆盖。

待你上板确认实际动作、重启保留及故障注入结果后，才能关闭硬件验收项。
