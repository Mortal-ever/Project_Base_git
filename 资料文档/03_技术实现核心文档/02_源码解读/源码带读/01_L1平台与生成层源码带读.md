# 01_L1 平台与生成层源码带读

> 只读 Review 分层文档（2026-09-02）。配套主文档：`00_Coffee2工程架构分析.md`。
> 本层 = CubeMX 生成物 + startup + 链接/内存配置。维护输入
> `CubeMX_Base/CubeMX_Genarate/{CMAKE,MDK}/*.ioc` 只读，禁止编辑生成输出。

## 1. 本层职责

- MCU 启动（startup→main→RTOS）；时钟（HSE/PLL→168 MHz）与 HAL。
- 外设初始化：GPIO、UART1-6、SPI1、ETH、RTC、CRC、DMA、TIM6 时基。
- 中断向量与 `stm32f4xx_it.c`；FreeRTOS V10.3.1（CMSIS-RTOS V2）；lwIP 2.1.2。
- 平台启动入口 `freertos.c`（创建 defaultTask 并选择 Target manager）。

## 2. 本层不负责什么

- 无产品业务/命令/设备绑定（L4）；无协议栈/传输/设备驱动（L2/L3）；
  无 Coffee2 状态与日志语义。

无（最底层）。被 L2/L3/L4 依赖。

## 8. 本层调用者

- `freertos.c:StartDefaultTask` 调 `MX_LWIP_Init()` 与 `vAppTaskManagerRunDefaultTask`。
- L2 `app_crash_diag.c`、L4 `coffee2_manager.c` 通过 HAL/FreeRTOS/lwIP API 使用本层。
- L2 Transport 直接消费 `huart*` 与 DMA 句柄（`transport_uart.c:32`）。

## 9. 初始化顺序（CONFIRMED，`main.c`）

1. `main`：关中断、`__set_BASEPRI(0)`、NVIC ICER/ICPR 三组清空、开中断
   （`main.c:108-124`）。
2. `HAL_Init`；`SystemClock_Config`：HSE+LSI、PLL M4/N168/P2/Q7 → 168 MHz，
   APB1 42/APB2 84、Flash 5 WS（`main.c:203-230`）。
3. `PeriphCommonClock_Config`：PLLI2S N50/R2（MCO2 用）（`main.c:237-250`）。
4. `MX_GPIO/DMA/SPI1/UART4/UART5/USART1/2/3/6/RTC/CRC_Init`（CubeMX 顺序）。
5. GCC USER CODE：`vAppCcmInit()`、`vAppCrashDiagInit()`、`dp83848_hw_reset()`、
   `HAL_Delay(5000)`；随后 `osKernelInitialize/MX_FREERTOS_Init/osKernelStart`。
   Keil 不调 `vAppCcmInit`（CCM 布局由 scatter 负责）。
6. `MX_FREERTOS_Init`（`freertos.c:85-118`）：`osThreadNew(StartDefaultTask)` +
   `xAppTaskManagerCreateTasks()`。
7. `StartDefaultTask`（`freertos.c:127-135`）：`MX_LWIP_Init()` →
   `vAppTaskManagerRunDefaultTask()`（不返回）。

> Coffee2 启动增强全部写在 USER CODE 区（`main.c:108-124,146-171`），符合
> `AGENTS.md:54` 保留 USER CODE 标记的要求。

## 10. 关键数据结构

- `UART_HandleTypeDef huart1..6`；`DMA_HandleTypeDef hdma_uart4/5/usart1/2/3/6_tx`
  （`usart.c:27-38`）——仅 TX DMA，无 RX DMA（接收为中断单字节入 StreamBuffer，
  见 02 文档 TransportUart）。
- `TIM_HandleTypeDef htim6`（HAL 时基）；`osThreadId_t defaultTaskHandle` +
  `osThreadAttr_t defaultTask_attributes`（`freertos.c:51-56`）。
- `struct netif gnetif`、`ip4_addr_t ipaddr/netmask/gw`、`IP_ADDRESS[4]` 等
  （`lwip.c:44-50`）。
- `RCC_OscInitTypeDef/ClkInitTypeDef/PeriphClkInitStruct`（`main.c` 栈上）。

## 11. 静态和全局对象

- CubeMX 句柄：`huart*`、`hdma*`、`htim6`、`heth`、`hrtc`、`hspi1`、`hcrc`。
- `defaultTaskHandle/defaultTask_attributes`（`freertos.c:51-56`）。
- lwIP：`gnetif/ipaddr/netmask/gw/IP_ADDRESS/NETMASK_ADDRESS/GATEWAY_ADDRESS`
  （`lwip.c:44-50`）。
- 平台层无 Coffee2 语义全局对象。

## 12. 任务上下文与 FreeRTOS 关键配置

- 内核 V10.3.1（`FreeRTOSConfig.h:3`）；tick 1000 Hz（`:69`）；`configMAX_PRIORITIES=56`
  （`:70`）；heap_4 32768 B（`:72,128`）+ `configAPPLICATION_ALLOCATED_HEAP=1`
  （`:177`）→ 堆对象放 CCM（`coffee2_manager.c:32-35`）。
- 栈溢出检测等级 2（`:79`）；`configASSERT` → `vAppCrashDiagAssertEntry`（`:158-163`）；
  traceTASK_CREATE/DELETE/SWITCHED_IN 接崩溃登记（`:180-197`）；FPU/MPU 关闭（`:60-61`）。
- defaultTask：栈 1024 B、优先级 `osPriorityNormal`（`freertos.c:52-56`），由生成代码
  创建（不属 Coffee2 manager）。
- lwIP：`tcpip_init` + `EthLink` 线程（1024 B，BelowNormal，`lwip.c:102-109`）。
- CCM 使用注意：CCM(0x10000000) 仅 CPU 可访问；FreeRTOS 堆/任务栈可放 CCM，但
  UART TX DMA 缓冲必须在 DMA 可访问 SRAM（`AGENTS.md:61-62`）。Transport UART 的
  `aucTxStorage[256]`/`aucRxStorage[256]` 在普通 SRAM 上下文中
  （`transport_uart.h:50-53`）。

## 13. 队列和同步对象

- L1 不创建业务队列；FreeRTOS 内部队列由 kernel 创建；`cmsis_os2` USER CODE 区留空
  （`freertos.c:90-117`）。
- Coffee2 队列（命令/订单/日志）全部由 L4 静态创建（见 04 文档）。

## 14. 关键函数带读

### Reset_Handler（startup）

- 文件：`GCC-ARM/startup_stm32f407xx.s`（Keil：`MDK-ARM/startup_stm32f407xx.s`）。
- 当前行号：`:60-102`（GCC）。
- 所属层：L1。调用者：复位硬件。被调用者：`SystemInit`、`__libc_init_array`、`main`。
- 运行上下文：特权线程模式、MSP。
- 输入/返回值：无。
- 读取状态：向量表与 `_sidata/_sdata/_edata/_sbss/_ebss` 链接符号。
- 修改状态：SP、.data 复制、.bss 清零。
- 阻塞：否。
- 正常路径：设 SP→SystemInit→复制 data→清 bss→__libc_init_array→main。
- 超时/错误路径：无返回；main 返回后落入未定义路径（`bx lr`）。
- 日志：无。RAM/栈/DMA：MSP 初值来自 `_estack`（RAM 顶）。
- 推荐断点：`:61`、`:100`。
- 必须回答：向量表[0]/[1] 是否为 `_estack`/`Reset_Handler`？CCM 由谁清零（GCC：
  `vAppCcmInit`；Keil：scatter `UNINIT` 且 startup 不清）？

### main

- 文件：`CubeMX_Base/Core/Src/main.c:105-171`。所属层：L1。
- 调用者：Reset_Handler。被调用者：§9 所列 Init/RTOS API。
- 运行上下文：调度器启动前 main 线程。
- 输入：无；返回值：无（死循环）。读取状态：NVIC/RCC。
- 修改状态：外设与 RTOS 全局。阻塞：`HAL_Delay(5000)` 阻塞运行。
- 正常路径：见 §9。错误路径：HAL Init 失败→`Error_Handler`（`main.c:282-291`）。
- 日志：无（调度器前早期失败由 L4 `prvWriteRawStartupFailure` 处理）。
- RAM/栈/DMA：GCC 必须先 `vAppCcmInit` 再创建 RTOS 对象（堆在 CCM）。
- 推荐断点：`:110`、`:150`、`:171`。
- 必须回答：为什么先清 NVIC ICER/ICPR？进入 RTOS 前 CCM/主 SRAM 是否就绪？

### SystemClock_Config

- 文件：`main.c:129-231`。调用者：main。被调用者：HAL_RCC_*。
- 正常路径：HSE + PLL(4/168/2/7) → 168 MHz。错误路径：`Error_Handler`。
- 推荐断点：`main.c:203`。问题：PLLQ=7 的 48 MHz 供谁？（ETH RMII/USB）

### vAppCcmInit（GCC）

- 文件：`GCC-ARM/Platform/app_ccm.c:16-25`。调用者：main（GCC 分支）。
- 读取/修改：`__ccm_bss_start__..__ccm_bss_end__` 清零。
- 问题：为何 CCM 堆/APP_CCM_DATA 不能交给 DMA？（CCM 非 DMA 可访问。）

### MX_FREERTOS_Init

- 文件：`freertos.c:85-118`。调用者：main。被调用者：`osThreadNew`、
  `xAppTaskManagerCreateTasks`（Coffee2）。
- 推荐断点：`:108`、`:111`。问题：业务任务为何在调度器启动前创建？

### StartDefaultTask

- 文件：`freertos.c:127-135`。调用者：调度器。被调用者：`MX_LWIP_Init`、

## 15. 正常路径（L1 范围）

Reset → 时钟 → 外设 → CCM/诊断 → 5 s 延时 → RTOS → defaultTask 建 lwIP →
Coffee2 manager 建任务 → 各业务任务就绪。

## 16. 错误和超时路径（L1 范围）

- HAL Init 失败：`Error_Handler()` 关中断死循环（`main.c:282-291`）。
- 栈溢出/malloc 失败/configASSERT：由 FreeRTOS 钩子进崩溃诊断（L2），实际输出介质在
  L4（`coffee2_crash_log_port.c`）。
- 5 秒延时期间业务尚未启动：设备上电稳定窗口，属平台约定。

## 18. RAM、Flash、栈和 DMA 注意事项

- 链接地址：Coffee2 FLASH `0x0800C000`+`0x54000`（OTA ld `:60`），与 Keil scatter 一致
  （`Coffee2_CCM.sct:5`）。向量偏移宏 `VECT_TAB_OFFSET=0x0000C000U`。
- CCM 64K：`.ccm_bss`（GCC，`app_ccm.c` 清零）或 `RW_CCM`/`CCM_APP`（Keil）；
  堆与任务栈可由 CCM 分配，但任何 DMA 目标不得在 CCM。
- UART TX：HAL 仅配置 TX DMA（`usart.c:33-38`），Transport 在普通 SRAM 保存
  `aucTxStorage[256]`（DMA 可访问）。RX 无 DMA，走单字节中断入 StreamBuffer。
- 主栈：`_estack = RAM 顶 - 8`（OTA ld `:64`）或 Keil `RW_IRAM2` startup STACK
  （`Coffee2_CCM.sct:18-20`），两者都是 0x2001C000 区域。
- 5 s 上电延时 + 各任务创建均发生在调度器启动前；CCM 堆必须早于第一个 xTaskCreate。
