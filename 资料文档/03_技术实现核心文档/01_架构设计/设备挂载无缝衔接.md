# Coffee2 设备挂载到已注册 Modbus RTU 的无缝切换分析

## 结论先行

**是的，Coffee2 已经完成了设备挂载到其他已注册 Modbus RTU 的无缝切换，且是否开启 DMA 都不影响其发送。**

下面从源码层面逐步证明这个结论。

---

## 一、Coffee2 的 RTU 总线架构

### 1.1 总线配置表（coffee2_rtu_bus.c:39-45）

```c
static const Coffee2RtuBusConfig_t s_axBusConfigs[COFFEE2_RTU_BUS_COUNT] = {
    { &huart2, "coffee2_bus2", COFFEE2_BUS2_DEFAULT_BAUD, 2U },
    { &huart3, "coffee2_bus3", COFFEE2_BUS3_DEFAULT_BAUD, 3U },
    { &huart4, "coffee2_bus4", COFFEE2_BUS4_DEFAULT_BAUD, 4U },
    { &huart5, "coffee2_bus5", COFFEE2_BUS5_DEFAULT_BAUD, 5U }
};
```

4 条物理 UART 总线（UART2~UART5），每条总线一个独立任务。

### 1.2 设备绑定表（coffee2_device.c:43-62）

```c
static const Coffee2DeviceBinding_t s_axBindings[] = {
    { COFFEE2_DEVICE_ROBOT,        0U, COFFEE2_ROBOT_UNIT_ID, 0U, 0U },
    { COFFEE2_DEVICE_COFFEE_MACHINE, 2U, 1U, 0U, COFFEE2_COFFEE_BAUD },      // Bus2 @19200
    { COFFEE2_DEVICE_CUP_MACHINE,   3U, 1U, 0U, COFFEE2_CUP_LID_BAUD },      // Bus3 @9600
    { COFFEE2_DEVICE_SYRUP_MACHINE, 3U, 2U, 0U, COFFEE2_SYRUP_BAUD },        // Bus3 @9600
    { COFFEE2_DEVICE_LID_MACHINE,   3U, 3U, 0U, COFFEE2_CUP_LID_BAUD },      // Bus3 @9600
    { COFFEE2_DEVICE_ICE_MACHINE,   4U, 1U, COFFEE2_ICE_MIN_FRAME_INTERVAL_MS, COFFEE2_ICE_BAUD },  // Bus4 @19200
    { COFFEE2_DEVICE_SCALE,         4U, 2U, 0U, COFFEE2_SCALE_BAUD },        // Bus4 @19200
    { COFFEE2_DEVICE_POWER_METER,   4U, 3U, 0U, COFFEE2_POWER_METER_BAUD },  // Bus4 @19200
    { COFFEE2_DEVICE_IO_INPUT,      5U, 1U, 0U, COFFEE2_IO_MODULE_BAUD },    // Bus5 @38400
    { COFFEE2_DEVICE_IO_OUTPUT,     5U, 2U, 0U, COFFEE2_IO_MODULE_BAUD }     // Bus5 @38400
};
```

**关键观察**：
- **Bus3 挂了 3 个设备**（杯机、糖浆机、盖机），波特率都是 9600 → 无需切换
- **Bus4 挂了 3 个设备**（制冰机、电子秤、电表均为 19200）→ 当前产品绑定无需波特率切换
- **Bus5 挂了 2 个设备**（IO 输入、IO 输出），波特率都是 38400 → 无需切换

因此当前产品的 Bus4 不依赖运行时切换：制冰机、电子秤和电表共用 UART4/19200。`prvSelectSerialProfile()` 仍保留真实的差异检测、Transport 关闭/打开和 UART 重配置路径，作为未来绑定表误配或迁移场景的防御性兼容机制；当前四条总线的产品绑定不会正常触发该路径。

## 二、无缝切换的实现机制

### 2.1 切换入口：prvSelectSerialProfile()（coffee2_rtu_bus.c:308-337）

```c
static ModbusPortResult_e prvSelectSerialProfile(
    Coffee2RtuBusContext_t *pxContext,
    Coffee2RtuBusStatus_t *pxStatus,
    const Coffee2DeviceBinding_t *pxBinding)
{
    // ① 波特率相同 → 无需切换，直接返回 OK
    if ((pxBinding->ulBaudRate == 0U) ||
        (pxBinding->ulBaudRate == pxContext->ulCurrentBaudRate)) {
        return MODBUS_PORT_RESULT_OK;
    }

    // ② 波特率不同 → 执行切换
    xTransportResult = xTransportClose(&pxContext->xChannel);   // 关闭 Transport 通道
    if (xTransportResult != TRANSPORT_RESULT_OK) return MODBUS_PORT_RESULT_TRANSPORT;

    xHalResult = prvConfigureUart(pxContext->xTransport.xConfig.pxUart,
        pxBinding->ulBaudRate);                                  // 重新配置 UART
    if (xHalResult != HAL_OK) return MODBUS_PORT_RESULT_TRANSPORT;

    xTransportResult = xTransportOpen(&pxContext->xChannel);    // 重新打开通道
    if (xTransportResult != TRANSPORT_RESULT_OK) return MODBUS_PORT_RESULT_TRANSPORT;

    pxContext->ulCurrentBaudRate = pxBinding->ulBaudRate;       // 更新当前波特率
    pxStatus->ulCurrentBaudRate = pxBinding->ulBaudRate;
    pxStatus->ulBaudSwitchCount++;                              // 统计切换次数
    return MODBUS_PORT_RESULT_OK;
}
```

### 2.2 切换动作拆解

**步骤①：xTransportClose()** → 调用 UART 后端 `prvClose()`（transport_uart.c:173-200）

```c
static TransportResult_e prvClose(void *pvContext)
{
    // 如果接收中断在运行，先中止
    if ((pxContext->xConfig.ucReceiveEnabled != 0U) &&
        (pxContext->ucRxPaused == 0U)) {
        xHalResult = HAL_UART_AbortReceive(pxContext->xConfig.pxUart);
    }
    pxContext->ucIsOpen = 0U;
    pxContext->ucRxPaused = 1U;
    return TRANSPORT_RESULT_OK;
}
```

**步骤②：prvConfigureUart()**（coffee2_rtu_bus.c:284-305）

```c
static HAL_StatusTypeDef prvConfigureUart(UART_HandleTypeDef *pxUart,
    uint32_t ulBaudRate)
{
    (void)HAL_UART_Abort(pxUart);          // 中止所有 UART 操作
    xResult = HAL_UART_DeInit(pxUart);     // 反初始化
    pxUart->Init.BaudRate = ulBaudRate;    // 设置新波特率
    pxUart->Init.WordLength = UART_WORDLENGTH_8B;
    pxUart->Init.StopBits = UART_STOPBITS_1;
    pxUart->Init.Parity = UART_PARITY_NONE;
    pxUart->Init.Mode = UART_MODE_TX_RX;
    pxUart->Init.HwFlowCtl = UART_HWCONTROL_NONE;
    pxUart->Init.OverSampling = UART_OVERSAMPLING_16;
    return HAL_UART_Init(pxUart);          // 重新初始化
}
```

**关键点**：`HAL_UART_DeInit()` + `HAL_UART_Init()` 会重置 UART 外设寄存器，但**不会改变 `pxUart->hdmatx` 和 `pxUart->hdmarx` 指针**。这两个指针是 CubeMX 在 `MX_USARTx_UART_Init()` 中静态绑定的，`HAL_UART_Init()` 不会清除它们。

**步骤③：xTransportOpen()** → 调用 UART 后端 `prvOpen()`（transport_uart.c:139-170）

```c
static TransportResult_e prvOpen(void *pvContext)
{
    // 重新启动中断接收
    xHalResult = HAL_UART_Receive_IT(pxContext->xConfig.pxUart,
        &pxContext->ucRxByte, 1U);
    pxContext->ucRxPaused = 0U;
    return TRANSPORT_RESULT_OK;
}
```

## 三、DMA 是否影响发送？—— 源码证明

### 3.1 发送路径的分支处理（transport_uart.c:351-398）

```c
static TransportResult_e prvTransmitRuntime(
    TransportUartContext_t *pxContext, const uint8_t *pucData,
    uint16_t usDataLen, uint16_t *pusSentLen, TickType_t xTimeoutTicks)
{
    // ★★★ 关键分支：根据是否配置了 DMA 选择发送方式 ★★★
    if ((pxContext->xConfig.pxUart->hdmatx == NULL) ||
        (pxContext->xConfig.pxUart->hdmatx->Instance == NULL)) {
        // ── 无 DMA：轮询发送 ──
        xHalResult = HAL_UART_Transmit(pxContext->xConfig.pxUart,
            (uint8_t *)pucData, usDataLen, prvTicksToMs(xTimeoutTicks));
        if (xHalResult == HAL_OK) {
            *pusSentLen = usDataLen;
            return TRANSPORT_RESULT_OK;
        }
        // ... 错误映射
    } else {
        // ── 有 DMA：分块 DMA 发送 ──
        xStart = xTaskGetTickCount();
        usOffset = 0U;
        while (usOffset < usDataLen) {
            usChunkLength = (uint16_t)(usDataLen - usOffset);
            if (usChunkLength > TRANSPORT_UART_TX_BUFFER_SIZE) {
                usChunkLength = TRANSPORT_UART_TX_BUFFER_SIZE;
            }
            xRemainingTicks = prvGetRemainingTicks(xStart, xTimeoutTicks);
            if (xRemainingTicks == 0U) return TRANSPORT_RESULT_TIMEOUT;
            xResult = prvTransmitDmaChunk(pxContext, &pucData[usOffset],
                usChunkLength, xRemainingTicks);
            if (xResult != TRANSPORT_RESULT_OK) return xResult;
            usOffset = (uint16_t)(usOffset + usChunkLength);
            *pusSentLen = usOffset;
        }
        return TRANSPORT_RESULT_OK;
    }
}
```

**结论**：发送逻辑通过检查 `pxUart->hdmatx` 是否为 NULL 自动选择 DMA 或轮询模式，**调用方无需关心是否开启了 DMA**。

### 3.2 DMA 模式下的 staging buffer 设计（transport_uart.c:402-437）

```c
static TransportResult_e prvTransmitDmaChunk(
    TransportUartContext_t *pxContext, const uint8_t *pucData,
    uint16_t usDataLen, TickType_t xTimeoutTicks)
{
    // 清空上次的完成信号
    while (xSemaphoreTake(pxContext->xTxDone, 0U) == pdTRUE) {}

    // ★★★ 关键：先拷贝到 staging buffer，再 DMA 发送 ★★★
    memcpy(pxContext->aucTxStorage, pucData, usDataLen);
    //       ↑ 这是 TransportUartContext_t 的成员，位于静态内存

    pxContext->ucTxError = 0U;
    pxContext->ucTxActive = 1U;
    xHalResult = HAL_UART_Transmit_DMA(pxContext->xConfig.pxUart,
        pxContext->aucTxStorage, usDataLen);
    //       ↑ DMA 从 staging buffer 读取，而不是调用者的缓冲区

    if (xHalResult != HAL_OK) {
        pxContext->ucTxActive = 0U;
        return (xHalResult == HAL_BUSY) ? TRANSPORT_RESULT_BUSY :
            TRANSPORT_RESULT_IO_ERROR;
    }

    // 等待 DMA 完成信号（由 HAL_UART_TxCpltCallback 给出）
    if (xSemaphoreTake(pxContext->xTxDone, xTimeoutTicks) == pdTRUE) {
        if (pxContext->ucTxError != 0U) return TRANSPORT_RESULT_IO_ERROR;
        return TRANSPORT_RESULT_OK;
    }

    // 超时 → 中止 DMA 发送
    pxContext->ucTxActive = 0U;
    xAbortResult = HAL_UART_AbortTransmit(pxContext->xConfig.pxUart);
    return (xAbortResult == HAL_OK) ? TRANSPORT_RESULT_TIMEOUT :
        TRANSPORT_RESULT_IO_ERROR;
}
```

**staging buffer 的意义**：
- 调用者传入的 `pucData` 可能位于栈上（如 Modbus 请求帧在 `nmbs_t->msg.buf` 中，这是结构体成员，位于静态内存，但协议层可能传入临时缓冲区）
- DMA 要求源地址在发送期间保持有效且可被 DMA 控制器访问
- 通过先拷贝到 `aucTxStorage`（`TransportUartContext_t` 的成员，位于静态内存），确保 DMA 源地址稳定

### 3.3 DMA 完成回调（transport_uart.c:640-665）

```c
void HAL_UART_TxCpltCallback(UART_HandleTypeDef *pxUart)
{
    // 找到对应的 Transport 通道
    pxChannel = prvFindByUart(pxUart);
    if (pxChannel == NULL) { ... }

    pxContext = (TransportUartContext_t *)pxChannel->pvContext;
    if (pxContext->ucTxActive == 0U) return;

    pxContext->ucTxActive = 0U;
    pxContext->ucTxError = 0U;
    pxContext->lLastNativeError = (int32_t)HAL_OK;

    // 给出完成信号，唤醒等待的发送任务
    xHigherPriorityTaskWoken = pdFALSE;
    (void)xSemaphoreGiveFromISR(pxContext->xTxDone,
        &xHigherPriorityTaskWoken);
    vTransportNotifyEventFromISR(pxChannel, TRANSPORT_EVENT_TX_COMPLETE,
        NULL, 0U, &xHigherPriorityTaskWoken);
    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}
```

## 四、波特率切换 + DMA 的兼容性验证

### 4.1 切换流程中 DMA 句柄是否丢失？

```
prvSelectSerialProfile()
    │
    ├── xTransportClose()
    │     └── prvClose() → HAL_UART_AbortReceive()   ← 只中止接收，不影响 hdmatx
    │
    ├── prvConfigureUart()
    │     ├── HAL_UART_Abort()                        ← 中止所有操作
    │     ├── HAL_UART_DeInit()                       ← 反初始化外设
    │     ├── 修改 Init.BaudRate 等参数
    │     └── HAL_UART_Init()                         ← 重新初始化
    │           └── 注意：HAL_UART_Init() 内部会检查 hdmatx/hdmarx
    │               如果非 NULL，会调用 HAL_DMA_Init() 重新配置 DMA
    │               （HAL_UART_Init 源码中: if (huart->hdmatx != NULL) { ... }）
    │
    └── xTransportOpen()
          └── prvOpen() → HAL_UART_Receive_IT()       ← 重新启动接收
```

**关键点**：`HAL_UART_Init()` 内部（STM32F4 HAL 源码）会检查 `huart->hdmatx` 和 `huart->hdmarx`，如果非 NULL 会重新初始化对应的 DMA 通道。所以 **DMA 句柄在波特率切换后依然有效**。

### 4.2 切换后发送是否正常？

切换完成后，`xTransportOpen()` 重新打开通道，`ucIsOpen = 1`。后续 `xTransportSend()` → `prvSend()` → `prvSendRuntime()` → `prvTransmitRuntime()` 会再次检查 `hdmatx`：

- 如果 CubeMX 配置了 DMA → 走 DMA 分块发送路径
- 如果没配置 DMA → 走轮询发送路径

**两种路径都能正常工作**。

## 五、完整验证：Bus4 统一波特率场景

```
场景: Bus4 上挂了制冰机、称重模块和电能表，三者均为 19200

1. 系统启动: Bus4 默认波特率 = 19200 (COFFEE2_BUS4_DEFAULT_BAUD)
   → xTransportUartCreate() + xTransportOpen()
   → ulCurrentBaudRate = 19200

2. 收到制冰机命令 (设备ID=ICE_MACHINE, 波特率=19200)
   → prvSelectSerialProfile(): 19200 == 19200 → 无需切换，直接执行
   → prvExecute() → xCoffee2IceMachineExecute()
   → xTransportSend() → prvTransmitRuntime()
     → hdmatx 非 NULL → DMA 分块发送 ✓

3. 收到称重模块命令 (设备ID=SCALE, 波特率=19200)
   → prvSelectSerialProfile(): 19200 == 19200 → 无需切换，直接执行
   → prvExecute() → xCoffee2ScaleExecute()
   → xTransportSend() → prvTransmitRuntime()
     → hdmatx 非 NULL → DMA 分块发送 ✓

4. 收到电能表命令 (设备ID=POWER_METER, 波特率=19200)
   → prvSelectSerialProfile(): 19200 == 19200 → 无需切换，直接执行
   → prvExecute() → xCoffee2PowerMeterExecute()
   → xTransportSend() → prvTransmitRuntime()
     → hdmatx 非 NULL → DMA 分块发送 ✓
```

当前产品绑定四条总线均使用一致的串口波特率，因此 `ulBaudSwitchCount` 在正常运行中应保持不变。若诊断发现绑定表与当前 UART 参数不一致，`prvSelectSerialProfile()` 仍可执行真实的关闭 Transport、重新配置 UART、重新打开 Transport 路径；这只是防御性兼容能力，不是当前 Bus4 的正常运行依赖。

## 六、结论总结

| 问题 | 答案 | 源码依据 |
|------|------|---------|
| Coffee2 是否支持设备挂载到已注册 RTU 总线？ | **是** | `s_axBindings[]` 绑定表 + `vCoffee2DeviceRegisterRoute()` 队列路由 |
| 当前产品是否允许同一总线配置不同波特率？ | **否** | 同一物理 Bus 的设备必须使用一致串口参数；`prvSelectSerialProfile()` 仅保留为误配或迁移时的防御路径 |
| 切换是否影响 DMA 发送？ | **否** | `HAL_UART_Init()` 会重新配置 DMA；`prvTransmitRuntime()` 自动检测 `hdmatx` |
| 是否开启 DMA 都不影响发送？ | **是** | `prvTransmitRuntime()` 通过 `hdmatx == NULL` 分支选择轮询或 DMA |
| DMA 模式下数据源是否安全？ | **是** | `prvTransmitDmaChunk()` 先拷贝到 `aucTxStorage` staging buffer 再 DMA |

**一句话总结**：Coffee2 当前产品要求同一物理 RTU Bus 使用一致串口参数；`prvSelectSerialProfile()` 只保留误配或迁移时的防御能力，正常运行不应触发波特率切换。`transport_uart.c` 的 `prvTransmitRuntime()` 仍按 `hdmatx` 自动选择 DMA 或轮询发送路径。
