# Coffee3Close 第二阶段详细业务流程说明

> 状态：SECOND_DRAFT / 待主人审核
> 日期：2026-09-01
> 目标：以 Coffee1 封闭式业务哲学为参照，定义 Coffee3Close 的完整目标流程
> 边界：只定义业务和物理行为，不复用 Coffee1 架构、源码或状态变量

## 1. 已确认的产品原则

1. Coffee3Close 是新 target，可以重新定义清晰的状态机、动作枚举和业务边界。
2. Coffee3Close 属于封闭式机型，整体流程哲学更接近 Coffee1 封闭式分支。
3. 当前硬件是 Coffee1 的减配版：保留机器人、咖啡机、杯盖机、糖浆机、制冰机、
   称重、电能表、1 组 16DI、1 组 16DO、本机 8DI/8DO，但储位和出餐机构减少。
4. Coffee1 只用于理解物理业务、分支、互锁、恢复和完成条件，不复制其代码结构。
5. 设备协议由公共 DeviceLibrary 提供；Coffee3Close 私有 Workflow 决定业务。
6. 残杯检查失败就是初始化失败。程序不提供继续、跳过或软件重试入口。
7. 人工取走残杯后必须整机复位，重新从上电开始执行完整残杯检查。

## 2. Coffee1 与 Coffee3Close 总体对比

| 业务项 | Coffee1 封闭式 | Coffee3Close 目标 |
| --- | --- | --- |
| 上电恢复 | 按机型分支，存在超时跳过和提前结束边界 | 统一严格初始化；任一残杯检查失败即锁定初始化失败 |
| 残杯处理 | 可搬到储位或出餐口，部分路径允许继续 | 不自动恢复；检测到残杯后停止，人工清理并整机复位 |
| 储位数量 | 最多 12 个，可配置启用位图 | 当前 2 个成品暂存位：X01 前、X02 后 |
| 出餐口 | 封闭式可有两个独立出餐机构 | 当前 1 个出餐口：X03，配合 DI1/DI2、DO1/DO2、X08 |
| 线上订单 | 制作完成后自动选择空储位 | 制作完成后选择 X01/X02 对应的空暂存位 |
| 现场订单 | 直接送指定出餐口 | 直接送唯一出餐口 |
| 付款后取餐 | 上位机指定储位和出餐口 | 上位机指定前/后暂存位，目标固定为唯一出餐口 |
| 咖啡机 | Coffee1 历史机型和多协议分支 | 固定 M50，UART2/115200/Unit1 |
| 果乳 | 多通道和旧 IO 板组合 | 固定 A/B 两路，Y15/Y16 阀、Y20/Y21 泵 |
| 奶 | 咖啡机指令与清洗阀协同 | 固定由 M50 指令完成，X11 做物料条件 |
| 出餐机构 | 多门、升降、风扇、灯带 | 单机构，仅 DO1/DO2、DI1/DI2、X03、X08 |
| 订单完成 | 制作、暂存、交付、顾客取走是不同生命周期 | 明确保留四个阶段，不用一个状态混合表示 |
| 失败清理 | 历史分支复杂，部分状态可能滞留 | 新 target 使用统一安全停止和按杯位置收尾 |

## 3. Coffee3Close 物理位置模型

软件至少维护以下物理位置状态：

| 位置 | 传感器 | 用途 |
| --- | --- | --- |
| 机器人夹爪 | 无直接传感器 | 通过搬运到可检测位置间接判断 |
| 咖啡机内部接液位 | 无直接杯传感器 | 上电残杯检查和制作接液 |
| 压盖位 | 无直接杯传感器 | 取盖、压盖和残杯检查 |
| 成品暂存位前 | X01 | 线上订单暂存、残杯检查 |
| 成品暂存位后 | X02 | 线上订单暂存、残杯检查 |
| 出餐口放杯位 | X03 | 现场直出和线上取餐交付 |
| 出餐机构上限 | DI1 | 门/升降机构到位 |
| 出餐机构下限 | DI2 | 门/升降机构到位 |
| 出餐安全区 | X08 | 顾客或异物进入时停止危险动作 |

任何动作开始前必须明确当前杯的逻辑位置；任何动作完成后必须由机器人完成位和
可用传感器共同更新杯位置。不能只根据“上一条命令发送成功”推断杯已经移动。

## 4. 上电初始化和残杯检查

### 4.1 初始化状态

```text
POWER_ON
 -> PLATFORM_INIT
 -> DEVICE_LINK_INIT
 -> WAIT_REQUIRED_SNAPSHOTS
 -> OUTLET_MECHANISM_HOME
 -> CHECK_DETECTABLE_POSITIONS
 -> CHECK_GRIPPER
 -> CHECK_COFFEE_POSITION
 -> CHECK_PRESS_POSITION
 -> FINAL_HOME
 -> READY
```

### 4.2 必须检查的内容

1. UART、TCP、GPIO、日志、Server 和各总线 Owner 已创建；
2. Robot、M50、杯盖设备、Bus5 输入快照已有效；
3. DO1/DO2 全部停止，出餐机构回到初始化安全位置；
4. DI1/DI2不能同时有效，X08不能处于危险触发状态；
5. X01、X02、X03必须处于可接受的空位状态；
6. 机器人回 Home；
7. 机器人把夹爪可能存在的杯搬到选定检测位，检查传感器；
8. 机器人检查咖啡机内部可能存在的杯，搬到检测位并检查；
9. 机器人检查压盖位可能存在的杯，搬到检测位并检查；
10. 检查落杯/落盖机构自身是否存在未处理物料或故障；
11. 机器人最终回 Home，重新确认 X01/X02/X03 和机构状态。

### 4.3 失败规则

以下任一条件成立，立即进入 `INIT_FAILED_LOCKED`：

- X01、X02、X03 任一位置发现残杯；
- 夹爪、咖啡机位或压盖位搬出残杯；
- 机器人动作失败、超时或无法回 Home；
- 出餐机构限位冲突或无法回到安全位置；
- 安全光栅阻止初始化动作；
- 必要设备状态无效，无法确定物理状态；
- 杯盖设备报告阻塞或无法判断状态。

`INIT_FAILED_LOCKED` 行为：

- 不接收订单；
- 不接受继续命令；
- 不接受清报警后从中间步骤恢复；
- 关闭泵、阀、加热器和出餐机构输出；
- 记录唯一失败位置和失败动作；
- 保持初始化失败状态直到系统复位；
- 人工移除残杯或障碍后整机复位，再执行完整检查。

这与 Coffee1 的部分“超时跳过、空位不足提前结束、继续恢复”路径不同，是
Coffee3Close 的明确产品规则。

## 5. 订单生命周期

Coffee3Close 将订单分为四个生命周期，不能用一个完成位混合表达：

1. `ORDER_ACCEPTED`：订单快照已冻结并通过校验；
2. `PRODUCT_READY`：饮品制作、加盖等生产步骤完成；
3. `PRODUCT_STORED` 或 `PRODUCT_AT_OUTLET`：杯已到暂存位或出餐口；
4. `CUSTOMER_TAKEN`：顾客已经取走，出餐机构完成复位。

线上暂存订单在 `PRODUCT_STORED` 后允许系统接收下一单，但不等于顾客已经取走。

## 6. 订单接收和准入

### 6.1 两阶段接收

1. 上位机写入订单字段；
2. Server 形成不可变快照；
3. 上位机确认订单；
4. Workflow 进行业务校验；
5. 校验成功进入制作；失败则报告原因并释放订单槽。

### 6.2 每单准入检查

只检查本订单需要的设备，但以下整机条件必须始终满足：

- 初始化状态为 READY；
- Robot 在线、使能且可接单；
- 输入/输出 IO 模块在线；
- X04 水源满足；
- X05 废渣箱存在；
- X06 废液桶存在；
- X07 废液未满；
- X08 安全光栅正常；
- 出餐机构无限位冲突；
- 当前没有清洗、加热、手动调试或 OTA 占用互斥资源。

按订单条件检查：

- 有咖啡或牛奶：M50 在线、空闲，X11满足奶条件；
- 冷饮：制冰机和称重模块在线且无故障；
- 有果乳 A/B：对应 X12/X13 满足且输出模块在线；
- 有糖浆：糖浆机在线且目标通道可用；
- 需要杯盖：杯盖设备在线、对应盖位有料；
- 线上订单：X01/X02 至少一个暂存位为空；
- 现场订单或线上取餐：X03 出餐口为空且机构可用。

## 7. 制作主流程

```text
VALIDATE_ORDER
 -> ROBOT_HOME
 -> SELECT_CUP
 -> DROP_CUP_AND_VERIFY
 -> 冷饮? ICE_AND_WEIGHT : 跳过
 -> 有果乳? FRUIT_A/B : 跳过
 -> 有糖浆? SYRUP_CHANNELS : 跳过
 -> 有咖啡/牛奶? M50_MAKE : 跳过
 -> 需要盖? DROP_LID_AND_PRESS : 跳过
 -> 线上单? STORE_PRODUCT : DELIVER_TO_OUTLET
 -> ROBOT_HOME
 -> REPORT_RESULT
```

### 7.1 杯型和落杯

- 根据冷热或杯型选择热杯/冷杯位；
- 机器人到落杯位；
- 先读取杯位状态，已有杯则不重复落杯；
- 无杯才下发落杯命令；
- 杯机事务成功后再次检查杯到位；
- 未检测到杯时停止流程，不得伪装为成功。

### 7.2 冷饮制冰

1. 机器人把杯放到称重/制冰位；
2. 称重去皮并检查杯重合理性；
3. 制冰机执行落冰；
4. 读取稳定重量；
5. 目标范围内完成；
6. 不足时按配置执行有限补冰；
7. 超重、无杯或补冰失败进入安全失败流程。

### 7.3 果乳 A/B

出液顺序默认 A 后 B，仅数量非零的通道执行。

正常出果乳 A：

```text
检查 X12
 -> 确保 Y15 按正常出液位置
 -> 打开 Y20
 -> 按校准时间运行
 -> 关闭 Y20
 -> 关闭/恢复 Y15
 -> 回读确认
```

果乳 B 使用 X13、Y16、Y21。A/B 首版串行，不同时开泵。

### 7.4 糖浆

- 根据订单通道逐路串行执行；
- 每路由糖浆机协议完成原子出液命令；
- 通信完成后必须结合设备状态确认该通道结束；
- 糖浆出液与糖浆清洗互斥。

### 7.5 M50 咖啡和牛奶

- 咖啡、牛奶或组合配方由 M50 命令完成；
- 发送前检查 M50 空闲和订单配方映射；
- M50 报告制作完成后，机器人再执行取杯动作；
- M50 成功不代表杯已经离开咖啡机；
- 配方号与现场菜单不一致属于配置错误，必须可诊断。

### 7.6 加盖和压盖

1. 根据订单选择盖位；
2. 杯盖机执行落盖并检查到位；
3. 机器人把杯移动至压盖位；
4. 执行取盖/压盖动作；
5. 动作完成后再进入储位或出餐路由。

## 8. 线上订单、现场订单和独立取餐

### 8.1 线上订单

1. 完成饮品和加盖；
2. 读取 X01/X02；
3. 优先选择前暂存位 X01，已占用则选择后暂存位 X02；
4. 两位均占用则不得开始该订单，制作前准入失败；
5. 机器人把杯放入选定暂存位；
6. 对应传感器确认有杯；
7. 上报暂存位和制作完成；
8. Workflow 回到可接单状态。

### 8.2 现场订单

1. 制作前确认 X03 无杯、出餐机构可用；
2. 制作完成后机器人放杯到出餐口；
3. X03 确认有杯；
4. 出餐机构按安全时序下降/打开；
5. 报告产品已到出餐口；
6. 等待顾客取走；
7. X03 无杯且 X08 安全后，机构复位；
8. 完整交付结束。

### 8.3 线上订单独立取餐

1. 上位机指定前暂存位或后暂存位；
2. 下位机检查对应 X01/X02 确实有杯；
3. 检查 X03 出餐口为空；
4. 机器人从暂存位取杯；
5. 放到出餐口；
6. X03 确认杯到位，原暂存位确认无杯；
7. 出餐机构开放；
8. 顾客取走后机构复位；
9. 清理本次取餐任务，不改变其他暂存杯状态。

## 9. 出餐机构安全流程

### 9.1 动作互锁

- DO1 和 DO2不得同时有效；
- DI1和DI2同时有效视为硬件异常；
- X08触发时立即停止 DO1/DO2；
- X03有杯时禁止机器人再次放杯；
- 机构动作必须有到位超时；
- 超时后先停止输出，再上报故障；
- 故障期间禁止新订单和独立取餐。

### 9.2 建议状态机

```text
OUTLET_HOME
 -> WAIT_PRODUCT
 -> PRODUCT_PLACED
 -> MOVE_TO_CUSTOMER_POSITION
 -> WAIT_CUSTOMER_TAKE
 -> SAFETY_CONFIRM
 -> RETURN_HOME
 -> OUTLET_HOME
```

## 10. 水路和热水任务

### 10.1 M50 水箱自动补水

- DI4 表示需要补水时打开 DO4；
- DI3 到位立即关闭 DO4；
- 最长补水 20 秒，超时关闭并报警；
- X04 无水时禁止启动补水；
- 高低液位矛盾时停止并报警。

### 10.2 热水桶注水和加热

1. 上位机触发热水任务并提供加热时间；
2. 检查 X04 水源和 DI5/DI6；
3. 打开 DO3 注水；
4. DI6 到位后关闭 DO3；
5. DI5 到位时无条件关闭 DO3并报高液位；
6. 注水超时关闭 DO3并失败；
7. 注水成功后打开 Y11；
8. 到达加热时间后关闭 Y11；
9. 取消、故障或复位时必须关闭 DO3和Y11。

## 11. 清洗任务

清洗是独立维护业务，不附属于普通订单步骤。

### 11.1 M50 咖啡管路清洗

- 仅在无订单、M50 空闲、出餐口可排水时启动；
- 下发对应清洗类型；
- 等待 M50 完整状态结束；
- 超时或失败时发送停止并记录具体阶段。

### 11.2 M50 奶路清洗

- 检查奶路/清洗水路条件；
- Y14按清洗设计打开或关闭；
- 向 M50 下发奶系统清洗；
- 完成或失败后确保 Y14回到安全状态。

### 11.3 果乳 A/B 清洗

- A：Y15 + Y20；B：Y16 + Y21；
- 每次只允许一路清洗；
- 清洗水从热水桶经管路到咖啡出口，再流入废液桶；
- 开始前检查 X06和X07；
- 完成、取消和失败均必须关闭阀泵。

### 11.4 糖浆机清洗

- 通过糖浆机协议启动；
- 与糖浆出液、果乳清洗和普通订单互斥；
- 状态由糖浆机反馈，不以单次写命令成功作为清洗完成。

## 12. 手动调试任务

Coffee3Close 应保留以下单步功能，但必须与自动业务互斥：

- Robot：使能、停止、Home、各工位点动；
- 杯盖：落杯、落盖；
- M50：单杯制作、停止、清洗；
- 制冰：去皮、出冰、重量读取；
- 糖浆：单通道出液和清洗；
- 果乳：A/B 单路阀泵调试；
- 本机 DO：DO1-DO8 位图调试；
- 外置 DO：Y11-Y26 位图调试；
- 出餐机构：上升、下降、停止；
- 热水：注水、加热、停止。

手动调试必须做到单次指令、单次响应、明确日志和安全最大动作时间。

## 13. 取消、失败和杯位置处理

| 失败阶段 | 杯可能位置 | Coffee3Close 处理 |
| --- | --- | --- |
| 落杯前 | 无杯 | 停止设备，回 Home，订单失败 |
| 已落杯 | 杯机位/夹爪 | 停止出液，尽可能放到空暂存位；否则锁定人工处理 |
| 制冰中 | 制冰位 | 停止制冰，记录重量，搬到空暂存位或锁定 |
| 果乳/糖浆中 | 接液位 | 关闭全部阀泵，停止糖浆，搬到空暂存位或锁定 |
| M50 制作中 | 咖啡机位 | 发送停止，等待安全状态；无法确认杯位置则锁定 |
| 压盖中 | 压盖位 | 停止机器人，禁止继续自动流程，人工处理或安全搬运 |
| 已在暂存位 | X01/X02 | 保留位置状态，不清杯状态 |
| 已在出餐口 | X03 | 保持出餐流程，不能回报为“杯不存在” |

自动回收只允许在物理位置和目标空位都明确时执行。无法确定杯位置时，宁可进入
锁定等待人工处理，也不能猜测并继续动作。

## 14. 断线和掉电

- 上位机 TCP 断线：已经确认的订单继续还是停止需产品最终确认；默认保持当前安全
  动作，不重复接单，重连后根据订单号和阶段恢复状态查询。
- Robot TCP 断线：停止推进新机器人动作；保留在途动作身份，重连后读取完成状态，
  禁止重复投递同一动作。
- RTU 设备断线：停止依赖该设备的当前步骤，关闭相关危险输出并进入失败清理。
- 掉电：不恢复进行中的订单动作；重启后无条件执行完整残杯检查。检查失败则保持
  初始化失败，人工处理并再次复位。

## 15. 日志要求

每个关键日志必须能直接回答：哪个订单、哪个设备/IO、哪个动作、哪个阶段、结果
如何、杯可能在哪里。初始化残杯失败只打印一次明确原因，不在循环中刷屏。

示例：

```text
[0000ERROR][C3Workflow:Init] INIT_FAILED LOCATION=COFFEE_POSITION REASON=RESIDUAL_CUP
```

## 16. 第二阶段审核项

本稿建议主人重点审核：

1. X01前暂存位、X02后暂存位、X03唯一出餐口的物理定义是否正确；
2. 线上订单是否固定优先前暂存位，再选择后暂存位；
3. 现场订单是否始终直达唯一出餐口；
4. 残杯检查是否覆盖夹爪、咖啡机、压盖位、两个暂存位和出餐口；
5. 初始化失败是否确认只能人工处理并整机复位；
6. 出餐机构是升降、门还是二者合一，DO1/DO2和DI1/DI2的动作语义；
7. 果乳正常出液时电磁阀应打开还是关闭；
8. Y14奶箱电磁阀在正常出奶和清洗中的实际位置；
9. 订单失败后是否允许自动把废杯放到空暂存位；
10. 上位机断线时已确认订单继续还是停止；
11. M50 菜单号、糖浆通道、杯盖位和机器人点位最终映射；
12. 热水注水、加热、补冰和顾客取餐的超时参数。

以上审核通过后，第三阶段才能冻结状态枚举、动作表、订单字段、错误码、超时表和
设备/IO依赖矩阵，再进入 Coffee3Close UserAPP 的源码设计。
