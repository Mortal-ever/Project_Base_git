**这些参数为什么这么改**
`MEM_SIZE = 24576`

这是 LwIP 自己的堆，不是 FreeRTOS 的 `configTOTAL_HEAP_SIZE`。TCP 收发、部分 pbuf、协议栈内部结构都会从这里分配。你原来的 `2048` 只适合 ping 或很轻的单连接，跑机器人 TCP、上位机 TCP、HTTP/Mongoose 很容易分配失败。

`PBUF_POOL_SIZE = 12`

pbuf 是 LwIP 收发网络包的缓冲块。以太网接收一帧、TCP 重组、排队发送都要用它。数量太少时表现为丢包、TCP 卡住、连接偶发断开。12 是 F407 上比较克制的起步值。

`PBUF_POOL_BUFSIZE = 1536`

以太网 MTU 通常是 1500，再加链路层头部和对齐开销，所以设到 1536 可以让一个 pbuf 基本装下一整帧。你之前 1024 会导致一帧可能拆成链式 pbuf，增加内存碎片和处理复杂度。

`TCP_MSS = 1460`

MSS 是 TCP 单个数据段最大载荷。以太网 MTU 1500 减去 IP 头 20、TCP 头 20，正好 1460。设成 1460 可以正常利用以太网效率。

`TCP_WND = 5840`

TCP 接收窗口，表示“我最多还能接收多少数据”。5840 = 4 * 1460，允许对端连续发约 4 个 MSS，不用每包都等 ACK。太小 HTTP 下载慢，太大占 RAM。

`TCP_SND_BUF = 2920`

TCP 发送缓冲，2920 = 2 * 1460。表示本端最多缓存约 2 个 MSS 的待发送数据。对 Modbus TCP 和普通 HTTP 请求够用，不会像 5840 那样吃更多 RAM。

`TCP_SND_QUEUELEN = 9`

这是发送队列允许挂多少个 pbuf。CubeMX 算出 9 是合理的，和 `TCP_SND_BUF`、`TCP_MSS` 有约束关系。它不是越大越好，太大占内存池。

`MEMP_NUM_TCP_PCB = 8`

TCP PCB 是 TCP 连接控制块。每个 TCP 连接都要一个。你预计机器人 TCP、上位机 TCP、HTTP/Mongoose、调试或临时连接，6 个比较合适。太小会出现 socket/connect/listen 创建失败。

`MEMP_NUM_TCP_PCB_LISTEN = 3`

监听型 TCP 控制块。上位机 TCP Server、Modbus TCP Server 这类 listen 端口需要它。3 个给未来扩展留一点余量。

`MEMP_NUM_TCP_SEG = 24`

TCP segment 是 TCP 待发送/待确认的数据段描述符。HTTP 或多个 TCP 同时传输时会消耗它。太小会导致发送卡顿或 `ERR_MEM`。

`MEMP_NUM_NETCONN = 8` / `MEMP_NUM_NETBUF = 6`

如果你用 socket/netconn API，每个连接和收发缓冲都会用到这些结构。Mongoose 通常走 socket，所以这里必须给够。

`MEMP_NUM_SYS_TIMEOUT = 12`

LwIP 内部定时器数量，比如 TCP 重传、ARP、DHCP、DNS 等。你开了 DHCP/DNS/TCP，默认太少会导致定时器分配失败，网络行为会很怪。

`LWIP_DHCP = 1`

让设备从路由器自动拿 IP。门店部署更方便。保留静态 IP 作为兜底也可以，但 App 第一版开 DHCP 是合理的。

`LWIP_DNS = 1`

后续 HTTP/Mongoose 访问云端域名必须要 DNS。不然只能写死 IP。

`LWIP_NETCONN / LWIP_SOCKET`

这是线程安全 API 层。FreeRTOS 多任务环境里不要直接乱用 raw TCP PCB。Mongoose 大概率需要 socket，所以必须打开。

`LWIP_NETIF_STATUS_CALLBACK / LINK_CALLBACK`

一个用于 IP 状态变化，比如 DHCP 成功；一个用于网线插拔/PHY 链路变化。你的设备要做断网重连、机器人 TCP 重连、上位机状态显示，这两个回调很有用。

总体目的就是：在 STM32F407VET6 RAM 不大的前提下，让 LwIP 同时容纳Robot Client、
一个1502监听器、三个外部ClientSlot及连接回收余量，而不是只够 ping。

**2026-07-17 当前代码侧最终值**

CubeMX生成结果已经确认 `MEMP_NUM_NETCONN=8`，但 `MilkTea.ioc` 当前没有
`MEMP_NUM_TCP_PCB` 条目。因此工程在 `LWIP/Target/lwipopts.h` 的
`USER CODE BEGIN 0` 中显式保存：

```text
MEMP_NUM_TCP_PCB = 8
LWIP_TCP_KEEPALIVE = 1
TCP_LISTEN_BACKLOG = 1
SO_REUSE = 1
LWIP_SO_LINGER = 1
LWIP_SO_RCVBUF = 1
```

不要仅凭CubeMX界面认为PCB已经生成成功；每次重新生成后应直接检查
`lwipopts.h`。当前ARM Compiler V5.06u7实编译结果为0错误、0警告，
`ZI-data=114860`字节。`LWIP_SO_RCVBUF`是MilkTea三槽Server调用 `FIONREAD`的必要
条件；关闭时 `lwip_ioctl()`会返回 `ENOSYS(38)`。
