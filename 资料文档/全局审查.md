## 1.1 五层架构
| 层               | 目录                                                         | 职责                                                         | 公共/私有            |
| ---------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | -------------------- |
| L1 平台/BSP      | `CubeMX_Base`                                                | HAL、FreeRTOS、lwIP、ETH、时钟、启动、USART GPIO             | 公共（唯一硬初始化） |
| L2 传输+协议栈   | `Transport`、`ProtocolStack/ModbusPort`、`New_Party/nanoMODBUS` | 字节通道抽象、Modbus RTU/TCP 端口、nanoMODBUS 栈             | 公共                 |

| L4 设备驱动+协议 | `DeviceLibrary`、`DeviceProtocol`                            | 型号驱动、无状态设备协议                                     | 公共                 |
| L5 产品应用      | `UserAPP/<Target>`                                           | 产品业务、设备/协议选型、静态参数/绑定、状态投影、任务编排   | **私有**             |

产品全局量，且未进入 Coffee2 的 CMake/Keil 源集；本轮标为 `OUT_OF_SCOPE`

## 1.2 依赖方向图
```
L5 UserAPP/Coffee2App  ──► L4 DeviceProtocol/DeviceLibrary
   │                          ▲
   └──► L3 Common(Command/Log/Ota/LwipAlert/TcpClientSession)
            ▲
```

除下一节定义的唯一启动组合适配器外，依赖只能由高层指向低层，**禁止低层反向依赖产品层**。

## 1.3 依赖规则
- **谁可依赖谁**：高层可依赖低层；L5→L4→L3→L2→L1 单向。
- **唯一组合边界**：`Application/Common/CommonTargets.h` 物理位于 Common，但语义上是启动期 Target 组合适配器，不是可复用公共 API；它可按 `USE_COFFEE2` 等 Target 宏包含所选 UserAPP manager。当前只有平台启动/组合根 `CubeMX_Base/Core/Src/freertos.c` 可以包含它，并通过该适配器调用 `xAppTaskManagerCreateTasks()`。
- **禁止反向**：除上述明确的组合适配器外，L1～L4 公共实现不得包含或调用 L5 UserAPP；不得再增加第二条公共层到产品层的反向依赖。
- **禁止跨层**：L5 不能直接碰 HAL 寄存器；L4 设备库不得包含产品头文件；L3 公共层不得引用产品 Config。
- **公共/私有判定**：除 `CommonTargets.h` 这一组合适配器外，`Common`/**`DeviceLibrary`**/**`DeviceProtocol`** 为公共——不含产品序号语义，只含设备范式、协议实现和命令契约。`UserAPP` 为私有——包含产品设备/协议选型、静态实例参数、总线绑定、任务编排和 Server 寄存器语义（如 `coffee2_device.c` 的 `s_axBindings`、`coffee2_server.c` 寄存器）。`DeviceModel/IO_State` 是带 MilkTea 语义的遗留例外，不归入当前公共基线。
- 公共层通过**通用接口 + 回调**与私有层解耦：如 `DeviceDriverDescriptor_t`、`DeviceCancelCheck_t`（`device_library.h:99-106`）、`AppOtaConfig_t`（`app_ota_flash.h:43-61`）。

## 2.1 启动链
复位 → `Reset_Handler`(startup) → `SystemInit`(system_stm32f4xx.c) → CleanNVIC(main USER CODE 1,`:109-123`) → `HAL_Init` → `SystemClock_Config` → `PeriphCommonClock_Config` → `MX_GPIO/DMA/SPI/UART4/UART5/USART1/2/3/6/RTC/CRC_Init` →（GCC）`vAppCcmInit` → `vAppCrashDiagInit` → `dp83848_hw_reset` → `HAL_Delay(5000)` → `osKernelInitialize` → `MX_FREERTOS_Init`（建 defaultTask + `xAppTaskManagerCreateTasks`）→ `osKernelStart`。defaultTask 里 `MX_LWIP_Init` 后调 `vAppTaskManagerRunDefaultTask`（网络监控）。
- 启动延迟 5 s：`main.c:163`（"确保上电后串口输出不被干扰"）。

## 2.2 Task_Manager（`coffee2_manager.c`）
- `xAppTaskManagerCreateTasks`：串行初始化 Transport/Log/ReadyEvents/Devices/Io/RtuBus/Robot/Workflow/Server，任一步失败返回负码并 raw 打印（`auc*FailMessage`），最多创建 8 个 Coffee2 业务任务：Server、Robot、Bus2-5、Workflow、Log；Log 依赖 transport 就绪。
- `vAppTaskManagerRunDefaultTask`：应用 IP 配置、置 `NETWORK_STACK_READY`、300 ms 轮询 `prvIsNetworkReady` → `prvPublishNetworkReady`（发布/清除 `NETWORK_READY` 事件 + 指示 LED）。
- `vAppTaskManagerWaitNetworkStackReady` / `ucAppTaskManagerIsNetworkReady` 供 Server/Robot 阻塞等网。

## 2.3 命令模型（历史记录；文件已删除）
- `AppCommandSource_e`：WORKFLOW=0 / SERVER=1 / MAINTENANCE=2。
- `AppAction_e`：公共 REFRESH=1/CANCEL=2/RESET=3；Robot 100-126；Coffee 200-203；杯/盖/糖浆/冰/秤/IO 300-350。
- `AppCommand_t` 32 B ABI（见 00）。`Coffee2Command_t`/`Coffee2Action_e`/`Coffee2CommandSource_e` 为其别名（`coffee2_device.h:40,60,135`）。
- **单订单身份匹配**：每个设备有独立 EventGroup（`COFFEE2_DEVICE_EVENT_*`），命令带 `ulOrderEpoch` 与 `ulCommandId`，`xCoffee2DeviceWaitCommand` 按 `(deviceId, orderEpoch, commandId)` 精确匹配，避免迟到终态；Coffee2 是单订单流程，不宣称多订单并行（`coffee2_device.c` 终端历史 6 槽/设备）。

# 03_工作设计.md（交付物 3）

## 3.1 设计准则为什么服务
- **资源受限下的分层**：128K SRAM + 64K CCM 中容纳五层架构 + lwIP + FreeRTOS + 双协议，靠"公共层只留范式、产品层才带具体资源"来控制占用（CCM 专放 FreeRTOS 堆与热数据）。
- **多产品复用**：同一公共源码树按 Target 编译裁剪；公共层（Transport/ModbusPort/DeviceLibrary/DeviceProtocol/Diagnostics/Command/Log/Ota）受控共享，产品层 `UserAPP/Coffee2App` 私有；MilkTea 本轮 `OUT_OF_SCOPE`。
- **双工具链一致**：`compiler_compat.h` 归一 ARMCC/GCC 的属性与段，`app_crash_fault_*.s` 双汇编，startup 各一份，保证同一套源码在 MDK 与 GCC 输出一致。
- **可维护性**：命令模型 32B ABI + 订单 epoch 身份校验、设备 EventGroup 隔离、日志结构化，使"订单-命令-设备"调用链清晰可追踪。

## 3.2 目标（一句话 + 可验证指标）
**目标**：在 STM32F407 上构建一套单订单串行、双工具链可复核、可 OTA 的模块化咖啡机固件。
可验证指标：
- **构建门槛**：Coffee2 Target 的目标为 0 error/0 warning；2026-08-29 Keil 已通过，GCC 修复后 9/9 新源和等价直接链接已通过，但标准 Ninja 受锁阻塞，仍不得写成双工具链标准构建均已通过。
- **SRAM 水位**：Debug RAM ≈98.8K/128K、CCM ≈40.9K/64K（08-13 记录），余量约 22%/36%（保守留 Bootloader MSP 掩码，`_estack` 低 8 字节）。
- **OTA 安全**：分区独立（metadata/staging/app），CRC 校验、写后读回、异常不改 metadata。
- **单订单串行**：命令异步但按 epoch 隔离 + 设备独立事件组，取消/超时/恢复（`prvAbortDevices`/`prvReconcile`）保证安全停。

## 3.3 工作模式
- **面向 Target 编译裁剪**：设计上由 `PRODUCT_NAME`/Target Define 选择 linker、源集和私有配置；当前 Keil Coffee2 清单与 GCC Coffee2 新 DeviceProtocol 清单均已同步，标准 Ninja 锁阻塞单独列为验证限制。
- **公共能力、私有选择**：DeviceLibrary/DeviceProtocol 提供公共实现；Coffee2 的设备型号、协议选择和物理绑定由 `UserAPP/Coffee2App` 与 Target 构建清单决定。
- **公共契约受控演进 / 私有层按产品扩展**：公共接口文件（app_command.h、device_library.h、modbus_port.h、app_ota_flash.h 等）保持兼容契约；产品扩展在 `UserAPP`，变更须补充验证证据。
- **命令-协议-设备三层消费**：Server/workflow → `AppCommand_t`（deviceId+action+param）→ 路由到 owner 任务 → 协议层(执行) → 设备驱动(帧/寄存器) → 状态回写镜像/事件 → 日志。
