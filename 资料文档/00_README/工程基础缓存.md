## 2. 公共/私有边界与目录路由

- 公共层：`Application/Common`、`Transport`、`ProtocolStack/ModbusPort`、
  `New_Party/nanoMODBUS`、`DeviceLibrary`。其 GCC 目标在产品分支外声明，Keil
  公共组只出现一次，任何 target 都可选择性 include/link。
- `DeviceLibrary/CoffeeMachine/coffee_machine_f200.*` 是公共 F200 驱动；它使用
  自有协议不改变公共属性。公共驱动只处理设备上下文、传输和设备结果，不处理
  target 命令、队列、寄存器或状态 image。
- `DeviceLibrary/CoffeeMachine/coffee_machine_O.*`、`coffee_machine_X.*`、
  `coffee_machine_m50.*` 是三个独立的公共 Modbus RTU 型号驱动；O/X 的状态区
  分别为 16/24 个寄存器，M50 沿用 Coffee1 的 16 寄存器控制集合。它们不包含
  Coffee2 头文件、物理总线绑定或业务命令枚举。
- 私有层：`Application/UserAPP/Coffee2App`，包含 Coffee2 流程、任务、命令、
  设备/总线选型、静态实例参数、设备 ID/route/unit/baud/IP/端口绑定、状态投影、
  日志 source 和 Server 寄存器语义。`coffee2_device_image.*` 属于此层。
- `Application/Common/CommonTargets.h` 是启动组合根例外，只由生成的 `freertos.c`
  按 target 宏选择私有 manager；它不是可复用公共业务 API。
- `Application/DeviceProtocol` 与 `Application/Common/Command/app_command.h` 已删除；
  不再建立公共命令转发层。旧 `ProtocolStack/Modbus`、`DeviceModel/IO_State` 为
  legacy/OUT_OF_SCOPE，不进入当前 Coffee2 正式链。
- 依赖固定为 `UserAPP -> DeviceLibrary -> ModbusPort -> Transport -> 平台`，
  公共层不得反向 include `UserAPP`。

## 7. Coffee2 IO 寄存器快照（2026-08-31）

- Coffee2 Server 不再提供旧版 IO 调试写动作。旧命令地址 `0x0084`-`0x0086`
  是保留空洞，FC06/FC10 只要覆盖该区间即返回非法数据地址；工作流内部正常
  IO 控制和公共 IO 设备库不受影响。
- 上位机使用三个只读保持寄存器：`0x10CC`（界面 4300）低 8 位为本机
  X1-X8，高 8 位为本机 Y1-Y8；`0x10CD`（4301）为外部 16 路输入 X1-X16；
  `0x10CE`（4302）为外部 16 路输出 Y1-Y16。位为 1 表示当前采样/缓存状态为 1。
- 本机映射经原理图、CMake/MDK 两份维护 IOC 和生成代码交叉确认：
  X1-X8=`PE0`-`PE7`，Y1-Y8=`PE8`-`PE15`。读取状态区时 Server 即时采样
  本机 GPIO；外部输入/输出来自 Bus5 owner 刷新的 Coffee2 私有状态镜像。
- 状态数组覆盖范围扩展到 `0x1000`-`0x10CE`。本次仅修改 Coffee2 私有
  Server 语义，未把产品寄存器下沉到公共层，也未修改 IOC、生成 GPIO 配置或
  Keil 虚拟目录。
- 验证：CMake 配置/生成通过；`coffee2_server.c` 使用最新生成命令独立编译
  0 error/0 warning。完整 Ninja 在当前执行环境无输出挂起，已停止等待，状态
  仍为 `CONFLICT`；未执行 Keil 构建和烧录。

### IO 刷新调度约束

- 本机 PE0-PE15 是 GPIO，可在 50 ms 周期采样；Server 读取 4300 时还会即时
  采样一次，因此本机状态不依赖 RTU 往返。
- 外部模组必须由 Bus5 单一 owner 串行访问。输入使用 Unit 1/FC02，输出使用
  Unit 2/FC01；两次事务不能在同一时刻并发。当前 Workflow 以 200 ms 周期提交
  输入和输出刷新，避免 115200/实际响应延迟下队列堆积；把两路都改为 50 ms 会
  超过单总线吞吐并造成队列满/超时，不建议。
- 已修复输出刷新动作此前只接受 `COFFEE2_ACTION_IO_WRITE` 的缺陷；现在
  `COFFEE2_ACTION_REFRESH` 调用 FC01 并更新 `aucMB2YPin`，FC05 写控制仍只由
  工作流内部使用。`result=-8` 的周期错误应在下载新固件后消失。
